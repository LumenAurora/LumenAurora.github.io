# 不动预训练，普通科研人员还能做什么：研究方向地图

> 预训练基座动不了，可研究的空间依然很大 —— 这恰恰是当前的主战场。本文按 PEFT、提示工程、RAG、推理优化与压缩、数据工程、Agent、对齐与后训练、评测、多模态、可解释性、测试时策略、模型编辑、模型系统等方向，系统梳理每个方向的核心思想、硬件需求与科研切入点。

垂直领域：特别是医疗、金融、政务场景。包括隐私去识别、越狱防护、敏感输出审计、知识泄漏检测，这些都很有现实需求。
常用推进手段：细粒度，动态化，主动call，可学习，端到端，任务扩展，多回合、多轮次。
学界的进化：数据集、bench——模型算法（架构创新，Scaling up）——后训练与thinking（有了thinking就有了反思和反事实）、agent——多轮、长上下文、速度——安全可信（对齐、危险问题拒答、不知道的问题拒答与模型自信度、回答忠实性、Fairness/Bias偏见与地域文化差异、Machine Unlearning、隐私（模型记忆泄露、模型推理过程与隐状态泄露任务无关输入信息）等）、模型分析（发现模型的普遍痛点，进行可解释研究，给出training-free Method）、不同算法路线的evaluation（统合模型的能力边界，指出缺陷之处；某些技术真的更为先进吗，我们真的在前进吗，我们应该在何时何任务选择何技术）、test-time computing、efficient AI（推理部署高效性，运筹学与管理优化理论调度大吞吐服务量）、infra、数据（数据效率、质量）、水印与模型溯源（文本水印区分AI与人工文本）——垂类应用、通用模型适配方法（adapter，《Robust Continual Test Time Adaptation via Visual Domain Adapter》）。反其道而行之，研究小参数量，小参数量也要搞推理等任务。
可靠性——面对不该变的扰动不能变（鲁棒性），面对该变的证据改变就要变（灵敏度），面对无法判断的应该弃权（透明度）
扩大对象：LLM——VLM、多模态——视频、音频，单轮对话——多轮对话，模型也有不同架构、dense——MoE。
diffusion那边也如此，一开始是几大生成模型轮番上场，然后流模型胜出并且统一了数学实质与它相同的算法，之后就是卷引导、编辑、加速了，以及跨不同模态、垂类应用。
常青树：不可能三角trade off，对抗领域（道高一尺魔高一丈）
## 课题生成
没有任何单一模式能在所有任务上占据主导。这就引出了一个关键问题：我们能否整合不同模式的互补优势，构建一个通用的视觉推理模型？
## 普通科研人员在大模型上的可研究方向

这是一个非常现实且重要的问题。事实上，**不动预训练**的前提下，可做的事情依然非常多，甚至是当前AI研究的主战场。

### 一、参数高效微调（PEFT）⭐ 最核心方向

预训练不能动，但可以**用极低成本微调适配下游任务**：

| 方法                | 核心思想                | 可训练参数占比  | 硬件需求   |
| ----------------- | ------------------- | -------- | ------ |
| **LoRA**          | 在权重矩阵旁注入低秩分解矩阵      | ~0.1%-1% | 单卡可跑   |
| **QLoRA**         | 4-bit量化 + LoRA      | 更低       | 消费级GPU |
| **Adapter**       | 在Transformer层间插入小模块 | ~1%-3%   | 单卡可跑   |
| **Prefix Tuning** | 在输入前添加可学习的虚拟token   | <1%      | 很低     |
| **Prompt Tuning** | 仅学习soft prompt嵌入    | 极低       | 很低     |
| **BitFit**        | 仅微调bias参数           | ~0.1%    | 极低     |
| **DoRA**          | LoRA改进，分解权重方向与大小    | ~0.1%-1% | 单卡可跑   |

**科研切入点**：
- 设计新的PEFT方法（如何用更少参数达到更好效果）
- 多任务/跨领域PEFT的组合与融合
- LoRA的秩选择、初始化策略研究
- 不同层的微调敏感度分析

LoRA神力：
我们通过低秩自适应（Low-Rank Adaptation, LoRA）（Hu et al., 2022）将 V-Skip 剪枝策略蒸馏（distill）到基础模型中，从而得到一个高效推理器，能够在推理时无需显式评分或在线过滤即可生成简洁且具视觉基础的推理依据。

### 三、检索增强生成（RAG）⭐ 应用热点
能优化的点很多：切块、索引、召回、重排、证据引用、多跳检索、表格和代码检索。
让模型**调用外部知识**，解决幻觉和知识时效问题：
本质是如何弄出高质量的向量嵌入。《TRACE: Task-Adaptive Reasoning and Representation Learning for Universal Multimodal Retrieval》让VLM先做推理，然后再把以上全部压缩为一个向量。

```
用户Query
   ↓
┌─────────────────────────────────┐
│  1. Query理解与改写              │
│  2. 检索（向量检索/关键词/混合）    │
│  3. 重排序（Reranker）           │
│  4. 上下文压缩与筛选             │
│  5. 增强Prompt构造              │
│  6. LLM生成                    │
│  7. 答案后处理与验证             │
└─────────────────────────────────┘
```

**科研切入点**：
- 检索策略优化（Chunking策略、Embedding模型选择）
- 多模态RAG（图文混合检索）
- Self-RAG（模型自主决定何时检索）
- 长文档RAG、多跳推理RAG
- 领域知识库构建（医学、法律、金融等）
- Graph RAG（基于知识图谱的RAG）

### 十五、模型合并
#### 什么是模型合并？

**模型合并（Model Merging）是一种将两个或多个已经训练好的大语言模型（LLM）的“知识”整合到一个单一模型中的技术**。

打个比方：假设你有两个助手，一个擅长数学解题，另一个擅长写代码。模型合并就像把这两个助手“合体”成一个全能助手——既会解题又会写代码，而且使用时只占一个人的工位（计算资源）。

与传统“模型集成（Ensemble）”不同——集成需要同时运行多个模型再综合它们的答案，**模型合并直接操作模型的内部参数（权重）**，合并后只得到一个模型，推理成本与单个模型完全相同。

更重要的是，**模型合并不需要额外的训练**，也不需要访问原始训练数据，这让它成为一种非常经济高效的技术。

---

#### 为什么要合并模型？

##### 1. 省钱省资源
训练一个LLM需要花费数百万美元的计算资源。微调（Fine-tuning）虽然便宜一些，但依然需要GPU集群。**模型合并可以在普通CPU上完成**，甚至不需要GPU。

##### 2. 变废为宝
在实际开发中，团队通常会做很多次微调实验，其中很多“失败”的模型虽然没达到预期效果，但依然学到了某些有用的能力。模型合并可以**重新利用这些“失败实验”的成果**。

##### 3. 组合专长
把擅长不同任务的模型合并成一个全能模型，无需从头训练。

##### 4. 保持推理效率
合并后的模型在推理时的计算成本，和单个模型完全一样。

---

#### 核心概念：权重、任务向量、任务干扰

在深入具体方法之前，先理解三个核心概念：

##### 权重（Weights / Parameters）
LLM本质上是一个巨大的数学网络，由数十亿甚至数千亿个“权重”（也叫参数）构成。这些权重决定了模型如何回答问题。你可以把权重想象成大脑里的神经连接——不同的连接强度决定了不同的能力。

##### 任务向量（Task Vector）
当我们针对某个任务（比如数学题）微调一个模型时，模型的权重会发生一些变化。**任务向量就是“微调后的权重”减去“原始基础模型的权重”得到的差值**。

用公式表示：**任务向量 = 微调后权重 - 基础模型权重**

这个向量代表了“为了让模型学会这个任务，权重发生了怎样的变化”。有了任务向量，我们就可以像搭积木一样，把不同任务的学习成果加减组合。

##### 任务干扰（Task Interference）
不同任务微调时，可能会修改**同一个区域的权重**，但修改的方向却不一样。就像两个人同时想调整同一个旋钮，一个要顺时针转，一个要逆时针转——这就产生了“冲突”（即任务干扰）。好的合并算法需要妥善处理这种冲突。

---

#### 主流模型合并方法（由简到繁）

##### 方法一：Model Soup（模型汤）

这是最简单直接的方法：**把多个模型的权重直接做加权平均**。

```
合并后权重 = α₁×模型1权重 + α₂×模型2权重 + ...
```

**优点**：实现极其简单，不需要复杂计算。  
**缺点**：如果模型之间的权重冲突严重，简单平均可能导致性能下降。

> 有一种“贪婪版”Model Soup：先按性能排序，逐个尝试合并，只有效果变好才保留，否则跳过。

---

##### 方法二：SLERP（球形线性插值）

SLERP是Model Soup的“升级版”。

简单平均是在两点之间走直线，但高维空间中的“直线”可能并不理想。SLERP则是在**高维球面上沿着最短弧线**进行插值，能更好地保留两个模型的独特特征。

**优点**：比简单平均更平滑，能更好地保留每个模型的特色。  
**缺点**：主要用于合并两个模型，扩展到多个模型时需要两两组合。

---

##### 方法三：Task Arithmetic（任务算术）

这个方法利用前面讲到的“任务向量”概念。

基本思路是：
1. 从每个微调模型中提取任务向量（微调后权重 - 基础权重）
2. 把这些任务向量加权求和
3. 把求和结果加回到基础模型上

用公式表示：**合并后权重 = 基础权重 + Σ(αᵢ × 任务向量ᵢ)**

**优点**：概念清晰，实现简单，是目前研究中**唯一被证实能在大语言模型上稳定提升性能的方法**。  
**缺点**：没有处理不同任务向量之间的冲突问题。

---

##### 方法四：TIES-Merging

TIES专门解决Task Arithmetic没处理的“任务干扰”问题。

它通过**三个步骤**来处理冲突：

1. **修剪（Trimming）**：只保留任务向量中变化最大的部分（比如前70%），其余置零——因为微调中很多变化其实并不重要。
2. **符号选择（Elect Sign）**：对每个权重位置，看各个模型想让这个权重增加还是减少，**少数服从多数**，选总幅度更大的那个方向。
3. **合并（Merge）**：只合并那些方向与“多数意见”一致的参数。

**优点**：有效减少了模型间的冲突，性能优于简单平均。

---

##### 方法五：DARE（丢弃与重新缩放）

DARE的核心发现是：**微调带来的权重变化中，大部分是冗余的，可以丢弃**。

它只需要三步：
1. 计算任务向量（微调后 - 基础）
2. **随机丢弃**其中大部分（比如90%）的变化
3. 把剩下的变化**放大**（比如放大10倍）再加回基础模型

神奇的是，即使丢弃了90%的微调变化，模型性能基本不受影响。

DARE可以单独使用（dare_linear），也可以和TIES结合使用（dare_ties）。

---

#### 方法对比总结

| 方法 | 核心思想 | 复杂度 | 处理冲突 |
|------|---------|--------|---------|
| Model Soup | 直接加权平均 | 极低 | ❌ |
| SLERP | 球面插值 | 低 | 部分 |
| Task Arithmetic | 任务向量求和 | 低 | ❌ |
| TIES-Merging | 修剪+符号选择+合并 | 中 | ✅ |
| DARE | 丢弃冗余+重新缩放 | 中 | 部分 |

#### 实操工具：MergeKit

目前最流行的模型合并工具是 **MergeKit**，由Arcee AI开发的开源库。

##### MergeKit的主要特点：
- **支持多种合并方法**：Model Soup、SLERP、Task Arithmetic、TIES、DARE等
- **低资源运行**：可以在CPU上运行，GPU显存最低只需8GB
- **支持多种模型架构**：Llama、Mistral、GPT-NeoX等
- **支持“弗兰肯合并”**：可以从不同模型取不同层拼凑成一个新模型

```yaml
models:
  - model: mistralai/Mistral-7B-v0.1  # 基础模型
  - model: WizardLM/WizardMath-7B-V1.0  # 数学专家
    parameters:
      density: 0.5
      weight: 0.5
  - model: codellama/CodeLlama-7b-Instruct-hf  # 代码专家
    parameters:
      density: 0.5
      weight: 0.5

merge_method: ties  # 使用TIES方法
base_model: mistralai/Mistral-7B-v0.1
dtype: float16
```

然后运行：
```bash
mergekit-yaml config.yaml output_folder
```

整个过程在普通CPU上大约需要几分钟到十几分钟。

#### 模型合并的应用场景

1. **多任务学习**：把数学专家、代码专家、翻译专家合并成一个全能模型
2. **能力迁移**：把一个模型学到的能力“转移”给另一个模型
3. **安全对齐**：把安全对齐后的模型与原始模型合并，平衡安全性和能力
4. **领域专业化**：把多个领域专家合并，用于跨领域任务
5. **联邦学习**：在保护数据隐私的前提下，合并各方的模型更新

---

#### 局限性与注意事项

1. **需要相同架构**：大多数合并方法要求模型具有相同的架构（比如都是基于Llama的）。不同架构的模型合并是更前沿的研究方向。

2. **不保证一定提升**：合并后的模型不一定比单个模型好，需要实验验证。

3. **方法选择很重要**：一项系统性研究发现，在真实场景中，**最简单的方法（Task Arithmetic）反而是最稳定有效的**。复杂的算法不一定更好。

4. **理论基础仍在探索**：为什么模型合并有效、什么时候有效，学术界的理解还在不断完善中。

---

#### 一句话总结

**模型合并 = 把多个已经训练好的模型的“知识”（权重）以数学方式组合成一个模型，不需要额外训练，省钱省力，还能把不同专家的能力集于一身。**

如果你对动手实践感兴趣，可以从MergeKit的GitHub仓库开始，用一个简单的YAML配置文件就能体验“合体”的乐趣！
