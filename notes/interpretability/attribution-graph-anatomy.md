# 归因图的解剖与因果干预配方

> 聚焦归因图本身的精确含义：节点到底是什么、边到底度量什么、归因图的完整构成，以及「注意力分析」一词在不同粒度下究竟指什么。最后给出一个可执行的因果证明配方（Teacher-Forcing 局部干预 + Attention Knockout + Path Patching + 双向验证）。

### 1. 节点到底是什么？

节点在早期研究中可能是整个注意力头或 MLP 层，但在你描述的那种“基于向量组分分解”的范式下，节点精确的组成是：

**一个三元组：( 层号 L, token位置 T, 特征编号 K )**

每个节点对应模型内部一个**可解释的向量方向**被激活的**强度**。具体拆开：

- **层号 L**：模型第几层的残差流（residual stream）或某一子层的输出。比如第 12 层残差流。
- **token位置 T**：当前输入序列中的第几个 token。比如“法国”这个词是第 3 个 token。
- **特征编号 K**：通过字典学习（如稀疏自编码器 SAE）得到的一个特定特征，或人为训练的探针方向。特征本质上是一个与模型隐藏维度等长的向量 `v_K`（比如维度 768），代表一个概念（如“城市”、“复数形式”）。
- **节点的“值”**：这个特征在当前层 L、当前 token T 上的**激活强度**，即把该位置的残差流向量 `x` 投影到 `v_K` 方向上的系数（对于 SAE 特征，就是稀疏编码的非零系数）。它是个**标量**（比如 5.2）。

**举例：** 节点 `(L=10, T=3, F=1024)` 表示“在第 10 层，第 3 个 token 位置，第 1024 号特征（可能代表‘法国’）的激活强度为 +5.2”。

**注意：** 同一个特征方向 `v_K` 在不同层、不同 token 位置是**不同的节点**，因为它们代表不同上下文下激活的同一个概念。

---

### 2. 边到底是什么？

边表示一个节点的激活**直接因果导致**另一个节点激活的**量**。

它的严格组成是：**一对有序节点 `(上游节点 N_src, 下游节点 N_dst)`**，并附有一个**因果效应权重 w**。

这个权重是怎么算出来的？不是相关性，而是通过**干预实验**来量化“如果上游节点改变了，下游节点会变多少”。核心方法是**归因修补（attribution patching）**或**激活替换（activation patching）**。

#### 具体计算方法（简化但本质如此）：
1. 让模型跑一个输入，记录所有节点激活值，称为**干净运行**。
2. 选定一条边，比如上游节点 `A = (L1, T1, F_src)`，下游节点 `B = (L2, T2, F_dst)`。
3. **干预上游**：把节点 A 的激活值人为改成一个“反事实”值（比如设为 0，或换成另一个输入的激活），而**模型其它所有部分完全不动**。这就是做了一次“因果干预”，只切断了 A 节点，其它路径原样保留。
4. **测量下游变化**：重新计算节点 B 的激活值，看它相对于干净运行时**改变了多少**。这个变化量 Δ 就是 A 对 B 的**间接效应（indirect effect, IE）**。
5. 边的权重 `w(A→B)` 就定义为这个 Δ 的大小（有时也带符号）。如果 Δ 很大，说明 A 对 B 的因果影响强；如果 Δ≈0，说明没有直接因果链。

**严格定义：** 边 `(A, B, w)` 意味着“当把特征 A 的激活固定为某个参考值，而保持整个模型其余部分不变时，特征 B 的激活值平均变动了 w”。

这个边捕捉的是**直接的、近似线性的因果贡献**，因为它隔离了 A→B 这条路径，而冻结了其他可能混淆的路径。

---

### 3. 归因图的完整构成

归因图就是这样一个集合：

```
图 G = ( 节点集 V, 边集 E )
V = { (L, T, K) | 激活值显著不为0 }
E = { (src_node, dst_node, weight) | weight 绝对值 > 阈值 }
```

实际构建时，研究者通常从**输出节点**（比如正确答案的 logit 对应的特征）开始，逐步回溯，只保留那些因果效应大于某个阈值的边，最终得到一个稀疏子图——这就是**可读的回路**。

---

### 一个具体到极端的例子

假设模型要补全句子：“The capital of France is __”。

**节点示例：**
- 节点1：`(层5, token“France”, 特征#127 )`——特征#127 的方向代表“欧洲国家”。
- 节点2：`(层5, token“France”, 特征#589 )`——特征#589 的方向代表“含有首都关系”。
- 节点3：`(层10, token“is”, 特征#304 )`——特征#304 的方向代表“下一个词应为城市”。
- 输出节点：`(层12, token“__”, 特征#77 )`——特征#77 的方向代表答案“Paris”。

**边及其权重：**
- 我们做干预实验：如果把节点1（“欧洲国家”）的激活值强制抹成 0，观察节点3（“下一词为城市”）的激活下降了 2.1。于是边 `(节点1 → 节点3, 权重=2.1)` 被记录。
- 类似地，`(节点2 → 节点3, 权重=1.8)`，`(节点3 → 输出节点, 权重=3.3)`。

把这些节点和边画出来，就得到了归因图：它告诉我们模型**先把“France”分解成“欧洲国家”和“首都关系”两个特征，然后在“is”处综合这两个特征，最后驱动出“Paris”这个答案特征**。

---

### 总结一下“严格由什么组成”

- **节点**：`(层, token位置, 特征方向ID)` 加上该处的**激活标量**。
- **边**：两个节点之间的**因果效应值**，通过**固定上游、测量下游变化**的实验严格获得，而不是相关性系数。
- **图**：由这些节点和边组成的稀疏有向图，是一个**因果模型**，用于解释模型如何把输入概念逐步转变成输出概念。

这样，“不透明的计算”就被转化成了一个节点是概念、边是因果链路的可读图。引导（steering）实验就是用这个图做操控，比如强制激活节点3，看输出是不是真变成城市名，以验证回路正确性。
简单来说，这篇文章在讲一个很实用的发现：**要想知道改动神经网络里的某个“特征”会不会改变模型的行为，不能光看这个特征本身代表了什么，而要看它连接了哪些“下游特征”。**

#### 什么是“下游特征”？
你可以把神经网络想象成一条多步骤的流水线。数据一层一层往深处传递，每一层都有许多“特征”（可以理解为负责识别或处理特定概念的小单元，比如一个专门负责“绿色”概念的特征）。

- **上游特征**：就是流水线前面站着的特征。
- **下游特征**：就是在这个特征之后、更靠近输出端的那些特征。这个特征激活后，会把信号传递给它，由它接着处理。

所以，“下游特征”就是一个特征在神经网络更深层所连接、所影响的其他特征。

#### 为什么下游特征很重要？
文章的核心思想是：**一个特征到底能引起什么行为，由它把信号传给了哪些“下游”来决定。**

作者举了例子：有两个特征A和B，它们看起来几乎一模一样——遇到“草是什么颜色”这种问题都会激活，而且都跟“绿色”强相关。如果只看表面信息，你会觉得它俩都很重要。

但**看它们各自的下游连接，真相就出来了**：
- **特征A的下游**：都连着处理“十六进制颜色代码”（比如 `#00FF00`）的特征。所以它虽然代表绿色，但代表的是“作为代码数值的绿色”，不管“用语言说出颜色”这件事。
- **特征B的下游**：连着一些更通用的特征，其中甚至有一个专门负责“说出‘green’这个词”的特征。

结果就是，如果你人为抑制（关掉）特征A，模型回答“草是什么颜色”时，照样会说绿色。但如果你抑制特征B，模型就可能把答案从“绿色”改成“红色”。**特征B才是真正在语言上输出“绿色”的元凶，特征A只是在另一个场景（写颜色代码）里有用。**

#### 一句话总结
**“下游特征”就是一个特征在神经网络里负责“接下来交给谁办”的那帮接盘侠。** 通过看它接着激活了哪些更深的特征，我们就能更准地判断：掐掉或增强这个特征，到底会不会改变模型最后说出来的话、做出的行为。这比光看这个特征自己对什么词敏感要可靠得多。
## 注意细节
这是一个非常好的问题，触及了LLM可解释性研究中"注意力分析"这个术语的核心模糊性。让我系统地梳理一下。

### 注意力分析的精确含义

你的观察完全正确——注意力是一个**多维度、动态变化**的对象。具体来说，一次完整的LLM推理产生的注意力数据可以表示为一个张量：

$$\mathcal{A} \in \mathbb{R}^{L \times H \times T \times T}$$

其中 $L$ 是层数，$H$ 是头数，$T$ 是序列长度（包括所有已生成的token）。

所以当我们说"注意力分析"时，它并不是一个统一的操作，而是一族在不同维度上做不同聚合/选择的分析方法。下面按你提到的两个维度展开：

---

#### 一、自回归维度：时间步的选择

在自回归生成中，每一步 $t$ 都会产生一个新的query（第 $t$ 个token），它对之前所有token $1 \dots t$ 计算注意力。所以有几种常见做法：

| 策略 | 具体做法 | 典型场景 |
|------|---------|---------|
| **Last-step attention** | 只看最后一步 $t = T$ 的注意力分布 | 分析模型"最终决策"时关注了什么 |
| **Attention rollout** | 将所有步的注意力矩阵相乘/累积 $\prod_{t} A^{(l)}_t$ | 追踪信息从早期token到最终输出的流动路径 |
| **Attention flow / 累积注意力** | 对所有时间步的注意力做求和或平均 $\frac{1}{T}\sum_t A_t$ | 获得整体的"全局关注模式" |
| **Step-by-step分析** | 逐步追踪注意力如何随生成过程演变 | 分析模型在生成不同阶段的策略变化（如CoT推理中不同阶段） |

**关键点**：大多数论文如果没有特别说明，"注意力分析"默认指的是 **last-step attention**——即最终输出token对所有前序token的注意力。因为这一步直接关联模型的最终预测。

---

#### 二、层维度：跨层的处理

对于一次前向传播，不同层的注意力确实不同，且含义也不同：

| 策略 | 具体做法 | 含义 |
|------|---------|------|
| **单层分析** | 只看某一层 $l$ 的注意力 | 研究特定层的功能（如早期层做语法，晚期层做语义） |
| **Last-layer attention** | 只看最后一层 | 认为最后一层最接近最终输出决策 |
| **Attention rollout across layers** | 将不同层的注意力矩阵相乘 $A^{(L)} \cdot A^{(L-1)} \cdots A^{(1)}$ | 模拟信息从输入到输出的跨层流动（Abnar & Zuidema, 2020） |
| **多层聚合** | 对所有层求平均或加权 | 获得一个"综合"的注意力视图 |

---

#### 三、所以"注意力分析"到底指什么？

精确地说，一次注意力分析需要明确指定以下**四个坐标**：

```
注意力分析 = f(
    哪些层？        → layer selection  (特定层 / 最后一层 / 所有层聚合)
    哪些头？        → head selection   (特定头 / 头平均 / 特定功能头)
    哪些时间步？    → step selection   (最后一步 / 所有步累积 / 逐步)
    什么指标？      → metric           (原始权重 / 梯度加权 / rollout / 熵)
)
```

常见的具体分析范式举例：

1. **"看模型在回答问题时关注了哪些token"**
   → 通常是 last-layer, last-step, head-averaged attention weights

2. **"追踪context中某个关键信息如何影响最终输出"**
   → 通常是 attention rollout（跨层×跨步）或 gradient-weighted attention

3. **"分析不同head的功能分化"**
   → 单层、单步、逐头分析，配合probing或ablation

---

#### 四、一个重要的caveat

最后需要提醒的是，即使精确定义了上述四个坐标，**注意力权重 ≠ 重要性**，这是可解释性领域反复强调的：

- **Attention is not explanation**（Jain & Wallace, 2019）：注意力权重高不一定意味着该token对输出有因果影响
- 更可靠的做法是结合 **gradient × attention**、**attention ablation**（如LogitLens、patching）、或 **causal tracing** 来验证

所以，当你在论文中看到"注意力分析"时，建议始终追问：**它是在哪个层、哪个时间步、哪个头上、用什么聚合方式做的？** 如果论文没有明确说明，这本身就是一个可解释性的可复现性问题。

### 观测的粒度导致混淆种类
别担心，**你不知道这个现象太正常了**！因为这不是本科CS的“通识课”内容，而是**AI可解释性（Mechanistic Interpretability）**这个前沿细分领域里的专业术语。不知道说明你还没入这个“坑”，而不是CS白学了。

我用大白话给你拆解一下这段话到底在慌什么：

**1. 他们在干什么？（背景）**
大模型内部有海量的“神经元”，这些神经元密密麻麻缠在一起，我们看不懂。于是研究人员发明了一种“**转码器（Transcoder）**”——你可以把它理解成一个**“压缩翻译官”**。它的工作是把原本密集、混乱的神经元活动，压缩成稀疏（Sparse）、精简的“特征”，方便我们人类去理解模型在想什么。

**2. 他们在担心什么？（核心问题）**
假设原始模型是个“黑盒算法A”，转码器是“替代模块B”。我们往模型里塞进这个“替代模块B”后，发现模型的**最终输出结果（Final Output）**和原来一模一样。

**但是！** 这段话指出：**输出一样 ≠ 内部机制一样。**

**3. 为什么拿排序算法举例？（破解你的知识盲区）**
你说你是CS学生，知道排序算法。那就拿这个举例：

- 原始模型可能用的是**快速排序（Quick Sort）**；
- 你训练的转码器可能学成**冒泡排序（Bubble Sort）**。

**结果**：你输入 `[3, 1, 2]`，两者都给你返回 `[1, 2, 3]`（**外在表现一致**）。
**隐患**：快速排序在极端情况下的复杂度是 O(n log n)，冒泡是 O(n²)。如果模型面对更复杂的长文本（海量数据），冒泡排序可能就崩了、算力爆炸了，或者对某些特殊输入（边界条件）会犯错。

**推及到AI**：原始模型可能依靠“逻辑推理”得出答案，而转码器可能只是靠“记忆词频统计”蒙对了同一个答案。**如果机制不同**，当我们用这个转码器去研究模型的安全性或鲁棒性时，得出的结论就是**虚假的、不可靠的**。

**4. 那我们凭什么相信它们机制相同？（给研究生的答案）**
这是一个**尚未完全解决**的难题。目前研究者勉强安慰自己的理由是：

- **因果干预实验**：他们会对原始神经元和转码器中的特征进行“敲除（Ablation）”。如果强行关掉原始模型的某个神经元，模型会答错；强行关掉转码器里对应的那个特征，模型**同样**答错，而且**犯错的模式**（比如偏向哪个错误答案）也一模一样——这才算给出了“有说服力”的证据。
- 但这种证据只能覆盖被测试过的输入，没法覆盖无穷无尽的未知输入。所以，大家依然在担忧“**机制不忠实（Mechanistic Unfaithfulness）**”的问题。

**总结一句人话**：这就好比你修车，为了看清发动机怎么转，你拿一个3D打印的模型塞进去。车确实还能跑，但你**无法100%保证**这个模型里面的齿轮咬合方式，跟原装发动机里面的真实物理运动是一模一样的。而你引用的那段话，就是在质问这个“3D模型”到底靠不靠谱。

### CoT问题
teacher forcing vs free run
这是一个很好的问题，涉及到机械可解释性（mechanistic interpretability）中因果归因的核心难点。让我先搜索一下相关的最新方法论，然后给你梳理清楚。这个问题问到了机制可解释性（mechanistic interpretability）里一个非常核心的陷阱：**"总效应"（total effect）和"直接效应"（direct effect）的混淆**。你的困惑完全正确——如果你自由地（free-running）重新生成整段CoT，那么一旦某个视觉token被扰动，后面所有token都会变，这只能说明"视觉信息在某处进入了因果链"，但**无法定位到底是哪一个CoT token真正"读取"了这个视觉token**。因为文本是自回归的，token T的隐藏状态变了，会通过它自己被当作后续输入而"传染"给T+1、T+2……，这是一种**级联混淆（cascading confound）**，跟"T这一步的计算本身有没有attend到视觉token"是两回事。

下面是几类真正能解决这个问题的因果实验设计。

#### 1. 用 Teacher-Forcing 冻结上下文，把"总效应"拆成逐步的"直接效应"

关键技巧：**不要自由生成**。把原始（未扰动）生成出的CoT前缀，通过teacher forcing强行喂给模型，只在视觉token上做干预，然后只看**这一个位置T的下一token logit分布/概率**如何变化，而不去重新采样后面的token。

在LLM可解释性中，通常只patch最后一个token位置，但这种方法对VLM不适用，因为视觉信息分布在很多image token上。这也提示我们，视觉→文本的因果路径本身就和纯文本任务不同，直接套用ROME式的"只测最后一个token"是不够的，需要专门测试CoT中间某个具体位置T。

具体流程：
- **Clean run**：正常图片+prompt，得到完整CoT（含token T）和各层激活缓存。
- **Corrupted run**：扰动/替换/加噪 视觉token V（或直接ablate），但**其余所有文本token（包括T之前的CoT）通过teacher forcing锁定为clean run的原始token**。
- 只对比在位置T处，模型next-token分布/logit的变化（KL散度、logit diff等）。

这样，"后面所有token都会变"的问题被消除了——因为你根本没有让后面的token自由重新生成，你只是在一个**固定上下文**下问："如果T之前的一切都不变，只有视觉token V变了，T自己的预测会不会变？"这就是标准的activation patching / causal tracing范式：Activation patching closes this gap. It provides causal evidence that a particular activation, at a particular position, at a particular layer, lies on the computational path from input to output.这与单纯的probing不同：这种correlation和causation的区别很关键：probing是诊断性的，而activation patching是介入性的。

#### 2. Attention Knockout（阻断特定注意力边）——直接检验"T有没有看V"

比teacher forcing更精细的一步，是不去动视觉token本身的值，而是**只屏蔽从T到V这一条注意力边**（在某些层、某些head上，把attention weight强制置零或替换为均匀分布），其他所有attention边保持原样。如果屏蔽这条边后T的预测发生显著变化，就是非常直接的证据：T这个位置的计算**确实通过注意力机制读取了V**，而不是通过别的路径（比如V的信息先被写入了其他中间文本token，再被T间接读到）。

已有工作用类似思路验证视觉信息的读取位置，例如Basu et al. (2024) 使用因果追踪和注意力贡献在视觉问答场景中发现，VLM（如LLaVA）在回答多模态问题时会从LLM较早的因果层检索信息，其分析表明视觉信息可能被总结在一组一致的靠后视觉token子集中，并且该研究还通过注意力阻断（attention blocking）实验来检验这一信息传递假设。

#### 3. Path Patching——只沿特定计算路径传递干预效应

如果你担心"T的变化可能是通过某个中间文本token间接继承的，而不是T自己直接attend到V"，可以用**path patching**：只允许干预效应沿着"V → (某个中间head) → T"这一条具体路径传播，其余路径全部保持clean run的值不变。Path patching 相比 activation patching能实现更细粒度的归因：它将干预限制在特定的计算路径上。具体做法是先在corrupted输入上跑一遍，记录上游head传给下游head的激活，然后在otherwise-clean的前向传播中，只替换下游head输入处的这部分激活。这可以严格排除"信息是绕道传过去的"这种混淆。

#### 4. 双向验证：必要性（ablation）+充分性（restoration）

- **必要性测试**：在clean run上，只ablate/破坏视觉token V在T这一步能被attend到的表示，看T的预测是否**变差/改变**（说明V是必要的）。
- **充分性测试（restoration）**：反过来，在corrupted run（比如V被换成别的图/加噪）里，把clean run中V的激活**"贴"回去**（只贴到T这一层这一位置相关的计算里），看T的预测能否**恢复**成clean的结果。

两者都成立，才是比较强的因果证据；只做单向容易被"冗余通路"或"补偿机制"误导。

#### 5. VLM特有的坑：视觉信息是分布式的，不能只测单一位置

最后一个token的patching在VLM里90%到98%的输出都不变，因为视觉信息分布在整个token序列上而不是集中在一个点，全序列patching会得到非常不同的结果。所以在设计实验时，通常需要对**所有视觉token做扫描**（而不是猜哪个token重要），画出"layer × token position"的因果效应热力图，类似FCCT这类工作的做法：Fine-grained Cross-modal Causal Tracing (FCCT) 系统地量化对视觉物体感知的因果效应，对全部视觉和文本token、多头自注意力、前馈网络和隐藏状态三大核心组件、以及所有解码层进行细粒度分析。

#### 6. 一个容易被忽略的陷阱：patch本身要"in-distribution"

做替换/加噪时要小心引入新的混淆。对干扰输入的构造，Symmetric Token Replacement (STR) 优于高斯加噪，因为STR产生的是分布内的干预，能保留对定位有意义的句法/语义属性，而高斯加噪往往产生分布外的伪影或虚假信号。对视觉token同理：与其加随机噪声，不如用"反事实图像里对应patch的embedding"做替换（interchange intervention），这样至少保证了改变的是语义内容而不是制造了模型从未见过的激活分布。已有VLM工作正是这样做的：通过将干净图像中左右两个条带的视觉token embedding替换为反事实图像里对应位置的embedding来做干预，替换时确保两个patch区域颜色值一致，只改变顺序信息这一个变量。

#### 小结：给你一个可执行的"因果证明"配方

1. 生成一次clean CoT，记录token T和它之前所有token。
2. 用**interchange/counterfactual替换**（而非纯加噪）扰动某个视觉token V的表示。
3. **Teacher-force**T之前的文本上下文不变，只在T这一步测next-token分布的变化（KL/logit diff）——避免"全部重新生成"造成的级联混淆。
4. 如果效应显著，再用**attention knockout**单独阻断T→V这条边，确认效应确实来自"T直接attend到V"，而不是绕道其它token传过来的。
5. 有条件的话补一个**path patching**，把效应限制在具体的head/layer路径上，进一步排除"冗余通路"混淆。
6. 做**必要性+充分性**双向验证，并在多个视觉token位置上扫描（而不是只测最后一个token），因为VLM里视觉信息通常是分布式存储的。

这一整套下来，你得到的就不再是"扰动V之后整段话都变了"这种粗糙的总效应，而是"在固定上下文、固定其它路径的条件下，T这一步的计算确实依赖V"这种精确到token-token对、边级别的直接因果证据。

这是个非常关键的区分。你提到的"推理中途把图片撤掉、自由生成到底、看最终准确率"和我之前讲的teacher-forcing patching，其实是两种完全不同层级的因果实验，回答的是两个不同的科学问题。让我先确认一下你说的那类研究，再给你一个严格的对比框架。你说的这类研究（推理到中途把图片撤掉，让模型**自由生成**剩下部分，看最终准确率变化）和我之前讲的teacher-forcing patching，确实是两种不同层级的因果实验，它们甚至不是"谁更严格"的关系，而是**回答的科学问题从根本上不同**。下面给你一个严格的定义和边界划分。

#### 先明确两者的因果对象不同

这是最容易搞混的地方。你问的"CoT某个token是否真正用了某个visual token"，其实隐含了两种可能想问的问题：

- **问题A（系统级/行为级）**："从生成步骤k开始，模型的后续整条推理轨迹，是否还需要继续访问图像这个资源？"——这是关于**资源依赖模式**的问题，单位是"整段未来轨迹"。
- **问题B（机制级/局部）**："在token T这一步的这一次前向计算里，它的输出logit是否因果地依赖某个具体visual token V的激活值？"——这是关于**单次计算内部信息流**的问题，单位是"一个节点对另一个节点的直接贡献"。

自由生成回答的是A，teacher forcing回答的是B。它们用的都是"do-intervention"式的因果框架，但介入的变量和保持不变的边界完全不同。

#### 范式一：自由生成式撤除（Free-generation Ablation / 行为级因果测试）

**做法**：在生成到第k个token时，对资源做一次性do-intervention（如撤掉图像、替换图像、遮挡图像），此后**不再teacher force**，让模型完全自主地重新采样后续所有token，重复多次（因为自回归采样是随机的），统计最终答案的准确率/分布变化。

**这个范式在本质上估计的是"总效应"（total causal effect）**：把k之后所有可能的计算路径（不管信息具体是被第k+1个token读取，还是被第k+5个token读取，还是根本没被任何token显式读取而只是通过某种分布式表示影响了采样）都混在一起，只看最终宏观结果的漂移。

**它适合回答什么**：
- 模型的CoT前缀是否已经把图像信息"文本化"/"落地"成了充分统计量（sufficient statistic），使得后续推理不再需要真正的图像，只需要之前生成的文字就够了；
- 模型是否存在"先扫一眼图像、把结论提前想好，后面全是复述"这种**提前下结论（premature answer commitment）** 现象——已有工作在纯文本层面用类似逻辑做过验证：Anthropic的研究发现，用填充token（"..."）替换CoT后，多数任务上准确率并没有提升，这说明模型并没有真正利用这部分额外的测试时计算，而只是在"占位"这一发现的推广形式，就是"移除/替换某段内容后，让模型自由继续，看最终准确率是否变化"这一整套范式的经典应用，只不过原文用于纯文本filler token，同样的逻辑可以迁移到"移除图像"上。
- 这类结果直接支撑了对VLM CoT"表面忠实但实际上没有真正依赖图像"现象的诊断：已有研究明确指出，最终答案的正确性与推理链是否忠实于图像可能出现背离，正确答案不一定真的基于图像，错误答案反而可能反映了视觉上忠实的推理，仅评估最终准确率无法判断推理过程本身是否真的关注了视觉证据

**它的根本局限**：它给出的因果证据永远是"聚合的、轨迹级的"，**无法定位到某个具体的CoT token是否在其自身的前向计算中读取了某个具体的visual token**。因为一旦撤图之后自由重采样，从k+1开始所有token都变了，你观察到的准确率差异，可能是因为k+1这个token直接看不到图了，也可能是因为k+1token没变但k+7才真正需要图、而k+1到k+6的变化只是随机采样噪声导致文本路径发生了漂移进而在k+7处放大——这就是级联混淆，跟你最初的困惑完全一致。所以严格来说，自由生成范式测的是"**图像作为一种持续可用资源，对未来整条轨迹是否是必要的**"，而不是"某个token的计算是否用了某个视觉token"。

**样本要求**：由于每次重新生成都是随机采样，必须**多次rollout**（比如同一断点采样N次），报告的是准确率/分布这种统计量的期望变化，而不是单条轨迹的确定性变化。这跟teacher forcing下"单次前向、确定性对比logit"的做法完全不同。

#### 范式二：Teacher-forcing局部干预（Activation Patching / 机制级因果测试）

**做法**：把T之前（含T-1）所有token**锁定**为clean run中原本生成的token（不让模型重新采样），只在这个固定上下文里，对某个内部变量（某个visual token的激活、某条attention边）做do-intervention，然后只测**T这一步**（单次前向）next-token分布的变化。

**这个范式估计的是"直接效应"或"路径限定效应"（direct / path-specific effect）**：因为上下文被人为冻结，干预的影响不可能通过"改变了T之前的文本从而间接影响T"这条路径传播，唯一能变化T的输出的路径，就是"干预变量→（某些层内的计算）→T的隐藏状态→T的logit"这条**特定的计算路径**。这正是activation patching一类方法的设计初衷。

**它适合回答什么**：正是你原本想问的问题——"CoT里第T个token的生成，是否真的在计算上用到了第V个视觉token"。这是token-token对、甚至head-head对级别的定位问题。

**局限**：它是"离线"、"单点"的测量，天然假设"其余一切不变"这个反事实是有意义的——但对VLM而言，视觉信息往往是**分布式**存储在很多视觉token上的，如果只测某一个视觉token，即使这一个不重要，也不能说明视觉信息整体不重要；同时它无法告诉你"如果真的在实际部署中把图撤掉，模型整体行为会漂移多少"，因为它从不做真正的自由rollout。

#### 严格的边界划分（该用谁）

| 维度 | 自由生成撤除 | Teacher-forcing patching |
|---|---|---|
| 因果问题类型 | 总效应 total effect | 直接/路径效应 direct or path-specific effect |
| 上下文处理 | 撤除点之后完全重采样 | 目标位置之前全部锁定为原始token |
| 测量对象 | 最终答案/多步之后的分布（宏观） | 目标位置T的next-token logit（微观，单点） |
| 因果单位 | "资源"对"整条未来轨迹"的必要性 | "某内部节点"对"某一次计算"的贡献 |
| 是否需要多次采样 | 需要（随机重生成，报告统计量） | 不需要（确定性单次前向对比即可） |
| 能否定位到具体token-token依赖 | 不能，存在级联混淆 | 能，这正是它的设计目的 |
| 典型问题 | "模型是否需要持续看图，还是看一眼就够了""CoT是否只是表演，并未真正驱动答案" | "第T个词的生成，是否真的attend/依赖第V个视觉patch" |
| 适用阶段 | 诊断宏观现象、做忠实性/依赖性审计、发现"哪里可能有问题" | 精确定位机制、验证"为什么"，做电路级解释 |

#### 两者如何配合，而不是二选一

实践中一个合理的研究管线通常是**先宏观、后微观**：

1. 先用自由生成撤除法，扫描不同的撤除位置k（比如CoT进行到10%、30%、50%、80%处撤图），画出"撤图位置 vs 最终准确率下降幅度"的曲线。如果发现"CoT进行到30%之后撤图基本不影响准确率"，这提示"模型在前30%的CoT里已经把关键视觉信息文本化了"——这是一个粗粒度但重要的定位信号，告诉你**该去哪个区间做精细分析**，而不是从一开始就对着几百个视觉token和几十个CoT token做teacher-forcing patching（计算上不现实）。

2. 再针对第1步发现的关键区间，用teacher-forcing + activation patching / attention knockout做逐token、逐层的精细归因，确认"是哪个具体的CoT token，通过哪个具体的attention head，读取了哪个具体的视觉token"。这一步给出的才是你最初想要的、真正token-to-token级别的因果证明。

3. 最后可以做一个"回验"：把第2步定位出来的具体视觉token单独做patch/ablate（而不是撤掉整张图），看是否也能在自由生成的宏观层面复现出类似第1步观察到的准确率下降——如果能复现，说明微观机制和宏观行为是一致的，形成了从行为现象到内部机制的完整因果闭环；如果不能复现（比如单独去掉这一个token对整体准确率几乎没影响），则说明视觉信息存在**冗余编码**（多个视觉token共同承载了同一信息，patch掉一个不够），这本身也是一个有价值的发现，值得进一步用"多token联合patching"或者"子空间/方向性patching"去验证。

一句话总结你的困惑：**你说的"后面所有token都会变"，本质上是因为撤图后你还在做自由重生成——那一步实验回答的从来就不是"某个token是否使用了某个视觉token"，而是"图像作为一种资源对未来是否还必要"这个更粗的问题。要证明token级的因果使用关系，必须冻结上下文（teacher forcing），把干预效应限制在单步计算内，这样"后面全变"这个混淆就被结构性地消除了。**
