# 机制可解释性是什么：目标、手段与电路发现流水线

> 从「想让人类理解 AI 为什么这么做」这一朴素愿望出发，区分广义可解释性与机制性可解释性，并给出这一领域的三层目标（科学认知 / 安全保障 / 工程操控）、常用技术手段，以及「电路发现」的五步流水线。

公设：泛化源于共享计算，叠加线性性
- **可解释性（广义）**：想尽办法让人类理解“AI为什么这么做”。
- **机制性可解释性（狭义）**：专门去拆解AI大脑（神经网络）内部的“物理零件”和“计算线路”，弄懂“AI到底是靠什么样的通用计算流程来解决这一类问题的”。
目标：
- **科学认知层（理解本身）**：发现新知识、理解智能本质、解析训练动力学（对应你缺失的第3点和部分第5点）。
- **安全保障层（防御与对齐）**：形式化验证、对抗鲁棒性、风险审计、可扩展监督（对应你的第1、3点，并补全验证和审计）。
- **工程操控层（改造与优化）**：参数编辑、模块化组合、数据投毒检测（修复数据导致的不良电路）、高效的微调引导（对应你的第2、4点，并补全模块化）。
机械可解释性领域最终旨在实现具体的科学和工程目标。例如，我们希望能够：
-  监控人工智能系统是否有与危险行为相关的认知迹象（[第3.2节](https://arxiv.org/html/2501.16496v1#S3.SS2 "3.2 Using mechanistic interpretability for better monitoring and auditing of AI systems for potentially unsafe cognition ‣ 3 Open problems in applications of mechanistic interpretability ‣ Open Problems in Mechanistic Interpretability")）;
- 修改内部机制并编辑模型参数，使其行为更符合我们的需求（[第3.2.2节](https://arxiv.org/html/2501.16496v1#S3.SS2.SSS2 "3.2.2 Using mechanistic interpretability for better control of AI system behavior ‣ 3.2 Using mechanistic interpretability for better monitoring and auditing of AI systems for potentially unsafe cognition ‣ 3 Open problems in applications of mechanistic interpretability ‣ Open Problems in Mechanistic Interpretability")）;
- 预测模型在未见情境下的行为，或预测模型何时可能学习特定能力（[第3.3节](https://arxiv.org/html/2501.16496v1#S3.SS3 "3.3 Using mechanistic interpretability for better predictions about AI systems ‣ 3 Open problems in applications of mechanistic interpretability ‣ Open Problems in Mechanistic Interpretability")）;
- 改进模型推理、训练和机制，以更好地适应我们的偏好（[第3.4节](https://arxiv.org/html/2501.16496v1#S3.SS4 "3.4 Using mechanistic interpretability to improve our ability to perform inference, improve training, and make better use of learned mechanisms ‣ 3 Open problems in applications of mechanistic interpretability ‣ Open Problems in Mechanistic Interpretability")）;
- 从人工智能系统中提取潜在知识，以便更好地模拟世界（[第3.5节](https://arxiv.org/html/2501.16496v1#S3.SS5 "3.5 Using mechanistic interpretability for ‘microscope AI’ ‣ 3 Open problems in applications of mechanistic interpretability ‣ Open Problems in Mechanistic Interpretability")）。
手段：分解，解释（组件激活的原因；该组件被激活后发生的情况）
“电路发现”流水线的步骤如下：
1. 任务定义。对于我们想要研究的某个模型，我们选择模型可以执行的任务，以及网络执行该任务的数据集。这是一个基于概念的步骤，因为任务的定义是基于人类研究者如何定义任务分布。
2. 分解。在分解步骤中，人们通常将神经网络视为有向无环图（DAG），激活由节点表示，节点间的“抽象权重”由边表示。迄今为止，大多数工作选择了架构组件（第2.1.2节），如注意力头和MLP层，作为节点。然而，较新的研究也将SDL潜伏器用于节点(Marks等人，2024年)
3. 初步描述步骤：识别与任务相关的子图和无关子图。电路发现过程随后识别与任务相关的节点和边。通常采用因果干预，从一些“干净”和“反事实”数据集中抽取样本。电路发现方法通常基于迭代激活接线(Wang 等，2023; Chan 等人，2022a; Lieberum 等，2023)或积分梯度(Marks等人，2024年).
4. 一个迭代描述-验证循环。获得任务相关的子图后，下一步是单独描述每个节点或边的功能。这一步比之前的步骤更不公式化。研究人员依靠直觉，尝试为电路某个元件或边缘的功能创建可检验的假设，然后设计定制实验以验证或否定其假设。只有经过多次假设检验和实验，研究者才最终对自己的解释感到满意。在研究论文中，这一循环很少被明确说明，因为只呈现最终的描述。然而，Chan 等人 2022b详细说明理解归纳任务的过程，南达 2023b提供了另一种对此类循环的描述（基于Li 等人，2023).
5. 最终验证。电路通常基于三个属性进行评估(Wang 等，2023)：忠实度，指电路对整个网络行为的近似程度;极小性，评估子图中的节点是否多余;完备性，判断未包含在子图中的节点是否对任务行为重要。此外，还有其他临时验证方法。例如，Wang 等，2023根据他们的机械理解，生成对抗性的任务示例，而Shi 等人，2024设计一套关于电路效能的正式统计假设检验。
最实用的技术：steering vector、残差流注入与操纵，模型编辑，token prunning、efficiency、加速推理，模型合并，预测模型能力、输出、学习过程，为模型训练选择更好的数据和课程学习、监控训练过程
在机制可解释性（mechanistic interpretability）中，我们通常会把模型的激活（activation）分解为基于向量的组分，例如字典学习特征（dictionary learning feature）或探针方向（probe direction）。我们会研究哪些组分在感兴趣的转写文本（transcript）上被激活，以此推断模型可能用到了哪些内部表示（representation）；再把这些组分组合成归因图（attribution graph），把不透明的计算转写成清晰可读的回路（circuit），并用它们进行引导（steering），以检验其对模型输出行为的因果效应。

两个时间维度。在 Transformer 中，信息可沿两个维度流动。在一个轴上，处理跨层进行，经过固定数量的计算步骤。在另一个轴上，处理也通过注意力机制沿序列维度展开，该机制可回想并变换来自任意先前序列位置的信息。大脑并未如此清晰地区分这些功能。递归动态同时负责精炼大脑对当前语境的理解（类比层维度处理）和维持并整合先前语境（类比序列维度处理）。下述讨论的 LLM 工作空间与人类工作空间之间的若干差异，都与这一结构差异相关。

前馈架构。在标准 Transformer 中，一次前向传播内部没有内建的递归，信息经过固定数量的处理步骤从输入传播到输出。然而，一个前馈模型可以复现递归网络的功能，直至等于前馈深度的若干时间步（事实上，受此时间步约束，非递归模型严格更具表达力，因为递归模型对应于权重在各层被绑定的特殊情况）。因此，尽管人类大脑中全局工作空间的动态被认为整体涉及递归连接，但任何此类递归计算原则上都可由 Transformer 在短时间尺度上模拟。在更长时间尺度上，模型将其审议（deliberation）延伸到前馈深度之外的唯一手段是将其外部化，将中间结果作为词元写入语境，并在后续位置读回。事实上，将词元的输出与随后的重新摄入视为模型利用其工作空间进行计算的方式之一或许是合理的；如此观之，模型类工作空间的处理在串行深度上是无界的，但在规则间隔处被显著带宽约束所打断。相比之下，人类工作空间可由高带宽的递归动态随时间维持，允许一个想法在无限数量的处理周期中被保持并细化，而无需显式言语化。

Transformer 注意力机制。沿词元轴，Transformer 注意力机制允许语言模型从语境中更早的位置检索任何内部表示（前提是它已在更早的层被计算）。这使语言模型的工作空间无需维持并传播状态。人类工作记忆没有这样的无损存储：其容量严重受限
[144, 10]
，并在数秒内衰退，因此片刻之前工作空间的内容已部分消失。LLM 的每个词元位置工作空间也有限，一次大约容纳数十个概念（§4.2），但其对过去的访问并非如此。这种安排并非完全没有人类类比：工作记忆的"活动沉默"（activity-silent）解释认为，条目可维持于短暂的突触变化中而非持续放电，并在被提示时重新激活
[145, 146]
，且已知 Transformer 式注意力与此类突触记忆机制之间存在数学关系
[147, 148, 149, 150, 151]
。但 Transformer 架构可能让语言模型比人类更重度且更可靠地利用这一策略，结果是语言模型工作空间的内容可能沿词元维度比人类工作空间随时间演化得更具不连续性。

在早中期层，表征过渡到编码当前局部上下文（例如，当前短语或句子）的情感内涵  
中后期层表征编码与预测下一个或几个标记相关的情感概念（“计划的情感”表征）

## 走进可解释性
用一句话帮你概括的话：

- **可解释性（广义）**：想尽办法让人类理解“AI为什么这么做”。
- **机制性可解释性（狭义）**：专门去拆解AI大脑（神经网络）内部的“物理零件”和“计算线路”，弄懂“AI到底是靠什么样的通用计算流程来解决这一类问题的”。

为了让你更清楚，我结合你提供的这段学术文本，把它们的区别拆成三个层次来讲：

#### 1. 广义的“可解释性”是什么？（一个“大筐”）
在学术界，可解释性是一个很大的概念，你给的文本里提到了**两条传统老路**，它们都属于广义可解释性，但关注点完全不同：

- **老路一：设计本身就可解释的模型**（早期做法）。
  - 比如用**决策树**或**线性模型**。这些模型结构简单，像“如果A大于B，就输出C”，人一眼就能看明白。这叫“内在可解释性”。
- **老路二：给“黑盒”模型做局部归因**（大模型兴起后）。
  - 比如用 **LIME、SHAP、Grad-CAM** 这些工具。它们不打开模型内部，而是通过“微调输入看输出变化”，来告诉你**“针对这一张具体的图片/文本，模型是看了哪些像素/词语才做出决定的”**。这关注的是**单个、具体的决策**。

---

#### 2. 核心概念：“机制性可解释性”到底是什么？
在你给的文本中，它被定义为**第三条研究线索**。它和前两条有本质的不同，核心特点有三个：

- **关注点不在“单个输入”，而在“通用能力”**：它不问“为什么这张图片是猫”，而是问“**模型普遍是如何解决‘识别动物’这类问题的**？”
- **拆解“内部电路”**：它把神经网络看作一个精密的电子设备，去找到里面具体的**“电路”**（比如某几个神经元组成的路径）、**“信息子空间”**（比如某个向量代表“性别”或“时态”），去研究这些物理组件在计算过程中是如何协作的。
- **寻找“共享的计算机制”**：它假设模型能举一反三（泛化），是因为内部有通用的计算规律。机制性可解释性就是要去逆向工程出这套规律。

#### 3. 最直观的区别对比（帮你彻底分清）

| 对比维度 | **广义可解释性（传统/归因）** | **机制性可解释性** |
| :--- | :--- | :--- |
| **核心提问** | “为什么**这个**输入得出了**这个**结果？” | “这个模型**内部结构**是如何计算**这一类**问题的？” |
| **研究工具** | 归因图、热力图（Grad-CAM）、SHAP值（看输入输出灵敏度） | 电路发现、特征可视化、词典学习（挖出中间层的隐藏向量） |
| **分析范围** | **局部**（针对单张图、单句话） | **全局**（针对整个任务类型，跨多个实例） |
| **模型态度** | 把模型当“黑盒”，从外部试探 | 把模型当“白盒”，打开看里面的“齿轮”和“线路”怎么转 |
| **典型例子** | 告诉你“AI识别这张狗的照片，是因为看到了耳朵和鼻子”。 | 告诉你“AI的某一层神经元里，有一个专门的‘狗耳朵检测器’，并且在处理所有带耳朵的图片时，都会激活这条固定的计算线路”。 |
