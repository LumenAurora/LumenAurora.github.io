# VLM 视觉编码全解：从固定分辨率到原生分辨率

> 系统梳理视觉语言模型中「如何处理任意尺寸图像」这一核心工程问题：从固定分辨率的局限，到 AnyRes 切块、混合编码器、原生分辨率（NaViT / NaFlex / Qwen2-VL），再到视觉 Token 压缩的五大路线，并给出横向对比与选型指南。

## 🖼️ VLM 视觉编码器动态处理图片尺寸技术全解

---

### 📌 第零章：前置知识——为什么图像尺寸是个问题？

#### VLM 的基本结构

在正式开始之前，我们先理解 VLM（视觉语言大模型）的基本组成：

主流 VLM 由四个部分组成：视觉编码器（Vision Encoder）、文本分词器（Text Tokenizer）、多模态 Token 投影层（Multimodal Token Projector）以及负责推理的大语言模型（LLM）。

其工作流程简单来说是：
1. **图像 → 视觉编码器** → 视觉 Token 序列
2. **文本 → 文本分词器** → 文本 Token 序列
3. **两者 concat → LLM** → 输出答案

#### 固定分辨率时代的局限

早期模型（如 LLaVA v1.5）依赖**静态预处理**，将所有图像强制缩放或填充到固定的正方形分辨率（例如 336×336），这是沿用传统计算机视觉的惯例。

这类"固定分辨率"方法（如 LLaVA-1.5、PaliGemma）先将输入图像缩放到固定尺寸再进行 VLM 编码，虽然计算效率高、结构简单，但往往难以充分捕捉复杂信息密集图像中的细粒度细节。

**问题的核心在于：**
- 把一张 1920×1080 的图强行压成 336×336，文字信息丢失严重
- 把一张竖版长图强行变成正方形，产生严重的**宽高比形变（Aspect Ratio Distortion）**
- 这直接导致 OCR、文档理解、细粒度识别等任务表现差

VLM 的准确率随输入分辨率提升而提高，尤其是对于需要理解细粒度细节的任务。

### 🧩 第一章：AnyRes——切块拼图的"分治"策略

#### 1.1 什么是 AnyRes？

AnyRes 是在 **LLaVA-NeXT**（LLaVA 1.6）中被系统性提出并命名的技术，它的核心思想极其直觉：**既然编码器只能接受固定大小的输入，那就把大图切成多块小图，每块分别编码，最后把所有 Token 拼起来！**

动态分辨率策略（以 AnyRes 为代表）允许 VLM 以图像的原生宽高比和分辨率来处理图像，其方式是将图像分割成固定大小的 Tile（图块）——这一约束源于视觉编码器依赖绝对位置嵌入的特性。

#### 1.2 AnyRes 的工作流程

AnyRes 是处理超高分辨率图像的一种流行方式：它将图像分割成多个较小的 Tile，通过视觉编码器分别处理每个 Tile，然后将所有 Token 传递给 LLM。同时，它还会对完整图像进行一次低分辨率编码，最终将所有 Token 一起送入 LLM。

用一个具体例子来理解：

```
原始图像: 1344×336 (宽图)
          ↓
┌─────────────────────────────┐
│ 按网格切分成多个 336×336 Tile │
│  [Tile1] [Tile2] [Tile3]   │
│                            │
│  + 一张缩放后的全局缩略图     │
└─────────────────────────────┘
          ↓
每个 Tile 独立通过 ViT 编码 → 576 Tokens
          ↓
全部 Token 拼接 → 送入 LLM
```

LLaVA-NeXT 采用与前代相同的架构，但专注于高分辨率和多图像输入。其 AnyRes 技术将高分辨率图像切分为多个子图像，全部分词后拼接起来，最终生成 2880（= 5×576）个 Token。

LLaVA-NeXT 在框架改进中加入了"AnyRes"动态分辨率处理技术，显著提升了视觉推理和 OCR 能力，且仅需极少量数据即可实现。

#### 1.3 切块网格的选择策略

AnyRes 并非随意切块，而是有一套**宽高比匹配**的选网格逻辑：

LLaVA-NeXT 和 Qwen2-VL 等现代架构采用了动态高分辨率预处理策略（通称 AnyRes）。受 NaViT 等架构启发，这些模型不再强制要求固定输入形状，而是利用基于网格的分解来适应图像的原始宽高比。AnyRes 将宽高比映射到不同的网格配置和图块数量。

LLaVA-NeXT 支持多种宽高比，最高支持 672×672、336×1344、1344×336 等分辨率，从而实现更好的视觉推理和 OCR 能力。

#### 1.4 AnyRes 的优点与缺陷

**优点：**
- ✅ 无需修改预训练视觉编码器的权重（兼容性强）
- ✅ 大幅提升高分辨率图像的识别精度
- ✅ 工程实现简单

**缺陷：**

动态分辨率方法通过自适应图像裁剪或原生分辨率编码来增强细粒度视觉信息的表示，但这些方法往往面临"分辨率困境"——视觉 Token 数量高度可变且过多，会带来显著的索引存储和计算开销。

Tiling 方式虽然有效，但可能破坏图像的全局结构，并引入冗余计算。

研究表明，VLM 更偏好语义上连续的视觉编码；Tile 数量越多的变体，往往不如 Tile 少的变体和静态分辨率变体表现好。

#### 1.5 AnyRes 的变体与继承者

LLaVA-OneVision 是进一步的迭代，通过引入"Higher AnyRes"策略，在单图、多图和视频场景中推动了性能边界，在部分基准上达到了与 GPT-4V 相当的水平。

此外：
- **InternVL 系列**：例如 InternVL2 使用约 36 个 Tile 来处理 2688×2688 分辨率的图像。
- **Qwen2-VL 系列**：Qwen2.5-VL 则训练了一种原生动态分辨率的 Vision Transformer（ViT），可以在保持原始尺寸的同时控制计算成本。

### 🧭 第二章：M-RoPE——多模态旋转位置编码

#### 2.1 什么是 RoPE？（铺垫）

RoPE（Rotary Position Embedding，旋转位置编码）是现代 LLM 中广泛使用的位置编码方案。它的核心思想是：**通过对 Query 和 Key 向量施加旋转矩阵，将相对位置信息编码进注意力计算中**，从而让模型感知 Token 之间的距离关系。

旋转位置嵌入（RoPE）通过在每个注意力头的查询和键向量上直接施加旋转矩阵来编码相对位置。设 $m$ 为 Token 的位置索引，$d$ 为注意力头的维度，RoPE 对每个 $2\times2$ 分块，以位置相关的角度 $m\theta_j$ 对一对维度进行旋转。

#### 2.2 1D RoPE 的局限：文本是线性的，但图像是二维的

在纯文本 LLM 中，序列只有一个维度（第 1、2、3…个 token），1D RoPE 完全够用。

**但图像不一样！**

LLaVA、Emu3、InternLM-VL、DeepSeek-VL2 等模型将图像 Token 展平为一维序列后与文本 Token 拼接，直接对整个多模态 Token 序列应用标准的 1D RoPE。

这样做的问题是：
- 图像的第 [2,0] 行第 0 列 patch 和第 [0,2] 行第 0 列 patch 在二维空间中等距，但展平后它们的 1D 位置 ID 相差 2×W（W 为图像宽度），**位置关系完全扭曲**
- 更严重的是，来自同一图像的视觉 Token——尽管语义上相似——仅因网格位置不同，就被 RoPE 编码为截然不同的距离。这种差异并非源于数据本身的关系，而是位置编码方法中的硬编码假设造成的，产生了不必要的相对位置偏差，扭曲了模型对跨模态关系的理解。

#### 2.3 M-RoPE 的核心设计（来自 Qwen2-VL）

M-RoPE（Multimodal RoPE）是 Qwen2-VL 团队提出的关键创新，它对 RoPE 进行了多维度拆解：

M-RoPE 是对传统 1D 旋转位置编码的创新性扩展，专为有效编码多种模态的位置信息而设计。它将原始旋转嵌入分解为三个独立的分量——**时间（Temporal）、高度（Height）、宽度（Width）**——分别适应文本、图像和视频中固有的空间与时间结构。

三种模态的处理方式分别为：


- **文本**：与传统 1D RoPE 相同，使用统一的位置 ID，序列线性递增。
- **图像**：为每个 Patch 分配独立的高度 ID 和宽度 ID，而时间 ID 保持为常数。
- **视频**：时间分量随帧数递增，而高度和宽度遵循与图像相同的方案。


用图示来理解：

```
文本 Token:
  位置 ID = (t=1, h=1, w=1), (t=2, h=2, w=2), ...  ← 三轴同步递增（退化为1D）

图像 Token (3×3 patch grid):
  (t=0, h=0, w=0)  (t=0, h=0, w=1)  (t=0, h=0, w=2)
  (t=0, h=1, w=0)  (t=0, h=1, w=1)  (t=0, h=1, w=2)
  (t=0, h=2, w=0)  (t=0, h=2, w=1)  (t=0, h=2, w=2)
  ← 时间固定，高/宽各自独立编码

视频 Token:
  第1帧: (t=0, h=0, w=0), (t=0, h=0, w=1), ...
  第2帧: (t=1, h=0, w=0), (t=1, h=0, w=1), ...
  ← 时间随帧递增
```

在 16 维的 M-RoPE 矩阵中，各维度按 **2:3:3** 的比例分配给时间、高度和宽度三个分量。

#### 2.4 M-RoPE 与动态分辨率的关系

M-RoPE 与 Qwen2-VL 的"Naive Dynamic Resolution"相辅相成：

Qwen2-VL 提供了：(1) 用于高效处理可变分辨率输入的原生动态分辨率；(2) 用于捕捉空间和时间结构的多模态旋转位置编码（M-RoPE）；(3) 整合了 2D 和 3D 卷积的统一架构，用于一致的图像和视频理解。

当图像分辨率变化时，Patch 的网格大小也在变化（例如 14×14 → 28×28），M-RoPE 的高度/宽度位置 ID 自然地适应了不同的网格大小，**无需固定网格尺寸**，这正是支持原生动态分辨率的关键。

#### 2.5 M-RoPE 的三大设计原则

研究者通过系统比较和大量实验，归纳出多模态 RoPE 设计的三个关键考量：**位置一致性（Positional Coherence）**、**完整频率利用（Full Frequency Utilization）**和**保持预训练 LLM 的文本先验（Preservation of Textual Priors）**。基于这些原则，研究者提出了 Multi-Head RoPE (MHRoPE) 和 MRoPE-Interleave (MRoPE-I) 两种即插即用的 RoPE 变体。

**更进一步的改进——Circle-RoPE：**

CircleRoPE 将视觉 Token 安排在与文本正交的圆形布局中，促进了跨模态注意力的均匀分布。

### 🌱 第三章：NaFlex——原生宽高比 + 灵活序列长度的编码器

#### 3.1 背景：NaViT 和 FlexiViT 的思想

在理解 NaFlex 之前，需要了解它的两大"思想来源"：

**NaViT（Patch n' Pack）：**
NaViT 沿空间轴对位置编码进行因式分解，使模型能够以原生宽高比处理任意分辨率的图像。 它的核心技术是"Patch Packing"——将多张图的 Patch 打包进同一个 batch 序列，避免了大量填充（padding）浪费。

**FlexiViT：**
FlexiViT 使用不同序列长度的输入，让单一模型能处理多种序列长度。

#### 3.2 NaFlex 是什么？

NaFlex 是 Google 在 **SigLIP 2** 中提出的动态分辨率变体，它融合了上述两种思想：

NaFlex 融合了 FlexiViT（支持多个预定义序列长度的单一 ViT 模型）和 NaViT（以原生宽高比处理图像）的思想，将宽高比失真降至最低，对 OCR 和文档图像处理等任务尤为有用。

SigLIP 2 的 NaFlex 整合了上述两大思想，将灵活的分块方式与可变序列长度相结合，从而改善了分辨率泛化能力。

#### 3.3 NaFlex 的具体工作流程

NaFlex 的预处理分为清晰的几个步骤：

**Step 1：智能缩放（保持宽高比 + 对齐 Patch 大小）**

给定 Patch 大小和目标序列长度，NaFlex 对数据进行预处理：首先将输入图像缩放，使得缩放后的高度和宽度均为 Patch 大小的整数倍，同时：(1) 将宽高比失真控制在尽可能小的范围内；(2) 生成的序列长度不超过目标最大长度（max_num_patches）。在宽度和高度方向上的失真分别不超过 (patch_size-1)/width 和 (patch_size-1)/height，对常见分辨率和宽高比而言这个误差极小。

**Step 2：切分 Patch + 填充 Mask**

缩放完成后，图像被切分为一系列 Patch，并附加一个包含填充信息的 Mask（用于处理实际序列长度小于目标长度的情况）。

用一个具体例子来理解：

```
原始图像: 1000×1000 (正方形截图)
patch_size = 16, max_num_patches = 1024

Step 1: 目标序列长度 1024 = 32×32 patches
        → 缩放至 32×16 × 32×16 = 512×512 像素
        → 宽高比完全保持 (1:1 → 1:1, 无失真)

Step 2: 切分为 32×32 = 1024 个 16×16 patches
        → 输出 1024 个视觉 Token

对于一张 2:1 的横向图像:
        → 缩放至 ~724×362（尽量接近1024个patch）
        → 精确分配为 44×22 = 968 patches
        → 用 56 个填充 Token 补齐到 1024
```

利用 NaFlex 预处理策略（max_num_patches=1024），在提取 Patch 之前将 1000×1000 的截图大致缩放到 704×704 像素，保持正方形宽高比。这一配置生成恰好 1024 个视觉 Token（32×32 的 16×16 Patch 网格），为识别按钮、图标和文本标签等小型 UI 元素提供了足够的空间分辨率，同时保持了计算效率。

#### 3.4 NaFlex 的关键优势

NaFlex 策略能够动态缩放图像，同时保持其原生宽高比（类似 NaViT），并允许可变序列长度（类似 FlexiViT）。

NaFlex 这一设计非常有价值，因为它使得单一模型既能用于 OCR（极小的宽高比失真）又能用于文档理解（适当的分辨率）。

NaFlex 是每种模型大小的**单一检查点**（single checkpoint），同时支持原生宽高比和可变序列长度/分辨率——而标准正方形输入 SigLIP 2 变体则需要为每种序列长度/分辨率单独准备一个检查点。

#### 3.5 NaFlex 的实际应用

LFM2-VL 使用 SigLIP2 NaFlex 编码器将输入图像转换为 Token 序列。

LFM2-VL 采用 SigLIP2 的 NaFlex 变体（类似 NaViT）作为视觉编码器，支持可变输入分辨率和原生宽高比。编码器输出 Patch 级别的嵌入，通过轻量级连接器投影到语言空间。该连接器首先应用 PixelUnshuffle 操作降低视觉 Token 数量，再通过 MLP 将图像嵌入映射到 LFM2 的隐藏维度。

部分研究工作选择 SigLIP-2 Base（patch size 16）的 NaFlex 变体作为视觉编码器，因其在 OCR 和文档理解基准上的卓越表现——这与需要精确文本识别和空间定位的计算机界面理解任务的需求高度契合。

### 🔁 第四章：三大技术的对比与关联

#### 4.1 技术对比总表

| 维度 | AnyRes | M-RoPE | NaFlex |
|------|--------|--------|--------|
| **本质** | 图像预处理策略 | 位置编码方案 | 视觉编码器训练范式 |
| **出处** | LLaVA-NeXT | Qwen2-VL | SigLIP 2 |
| **解决问题** | 高分辨率图像的信息损失 | 2D 空间结构的位置表达 | 宽高比失真 + 分辨率泛化 |
| **工作层** | 预处理层（编码器之前） | 注意力机制层（LLM 内部） | 视觉编码器训练层 |
| **是否修改编码器** | ❌ 不修改（黑盒使用） | ✅ 修改 LLM 的位置编码 | ✅ 专门训练编码器 |
| **Token 数量** | 大幅增加（成倍增加） | 不直接影响数量 | 灵活可控 |
| **宽高比保持** | 近似保持（选网格） | 通过 2D 坐标表达 | 原生精确保持 |
| **代表模型** | LLaVA-NeXT, InternVL | Qwen2-VL | SigLIP2, LFM2-VL |

#### 4.2 三者的继承与互补关系

```
问题: 如何处理任意尺寸的图像？
          ↓
┌─────────────────────────────────────────────────────────┐
│                                                         │
│  方案1: AnyRes（"分割再处理"）                            │
│  切成固定尺寸的Tile → 多个编码器实例 → Token拼接          │
│  优点：不改模型；缺点：破坏全局结构，Token爆炸             │
│                                                         │
│  方案2: NaFlex（"编码器原生支持"）                        │
│  训练编码器本身支持任意分辨率 → 保持宽高比 → 单次编码      │
│  优点：无结构破坏；缺点：需重训编码器                      │
│                                                         │
│  方案3: M-RoPE（"让LLM理解2D位置"）                       │
│  在LLM侧为视觉Token提供2D坐标 → 空间感知更精准            │
│  通常与方案2配合使用（Qwen2-VL = NativeDynRes + M-RoPE）  │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

#### 4.3 VLM 视觉编码策略的整体分类

现有的视觉编码策略可以大致分为三类——**固定分辨率（Fixed-Resolution）**、**动态分辨率（Dynamic-Resolution）** 和**混合分辨率（Hybrid-Resolution）**方法。

针对具有固定输入尺寸的视觉编码器，研究界主要探索了三种实现动态分辨率视觉编码的途径：(1) 上采样方法；(2) **基于裁剪的方法**（即 AnyRes 类）；(3) 混合视觉编码器方法（即高分辨率与低分辨率编码器的组合）。

此外，采用原生分辨率视觉编码器的 VLM 也开始涌现（如 Qwen2-VL、Kimi），它们通过保持图像的原始分辨率和宽高比提供了一条全新的路径。

### 🚀 第五章：技术演进路线图与未来趋势

```
时间线 ──────────────────────────────────────────────────────►

[2021] CLIP：固定 224×224，开创图文对齐时代
    ↓
[2023] LLaVA-1.5：固定 336×336，CLIP ViT-L 作为编码器
    ↓
[2024.01] LLaVA-NeXT：引入 AnyRes，支持多种宽高比网格切分
    ↓
[2024] NaViT：提出 Patch Packing，原生分辨率训练 ViT
    ↓
[2024] InternVL2：大规模应用 AnyRes，最多支持~36 Tiles
    ↓
[2024] Qwen2-VL：Native Dynamic Resolution + M-RoPE
    ↓
[2025.02] SigLIP 2 + NaFlex：单一检查点支持任意分辨率
    ↓
[2025~] 趋势：原生分辨率编码器 + 智能 Token 压缩
```

多模态大模型（MLLMs）的视觉编码器正在逐渐从复用固定分辨率主干网络向原生分辨率建模转变。传统固定分辨率 ViT 通常为对比性图像-文本匹配而预训练，其粗粒度表示往往不足以满足对细节敏感的下游任务需求，如 OCR、细粒度识别、文档理解和视频理解。

---

### 💡 总结

| 技术 | 一句话总结 |
|------|-----------|
| **AnyRes** | 把大图切成小Tile，分别编码再拼接——**治标**之策，简单有效，但代价是 Token 数量激增 |
| **M-RoPE** | 把 1D 位置编码升级为 2D（甚至 3D），让 LLM 真正"理解"图像的空间坐标——**治本**于位置感知 |
| **NaFlex** | 训练编码器原生支持任意分辨率和宽高比，单一模型适配所有尺寸——**治本**于编码器能力 |

三者共同服务于同一个目标：**让视觉语言大模型能够以最少的信息损失、最高效的方式处理现实世界中形态各异的图像。** 目前最先进的 VLM 往往将这三类技术组合使用——例如 Qwen2-VL 将原生动态分辨率 ViT（类 NaFlex 思路）与 M-RoPE 深度结合，代表了当前最前沿的技术路线。

## 🖼️ VLM 视觉编码策略：从固定分辨率到原生分辨率——完整发展史与技术全景

---

### 📌 第零章：读前必备——这一切问题的根源是什么？

在我们进入任何技术之前，必须先彻底搞清楚**痛点的根本来源**。

#### 0.1 图像和文本，天生就是两种不同的信息载体

文本是**天然离散、线性、等长**的：每个字符都是一个独立符号，排成一条线，天然有序。

图像是**天然连续、二维、尺寸多变**的：
- 一张护照照片可能是 600×800
- 一张横幅广告可能是 5000×500
- 一张医学CT扫描可能是 4096×4096
- 一张手机截图可能是 1080×2340

它们的**宽高比（Aspect Ratio）** 和 **分辨率（Resolution）** 千差万别。

#### 0.2 ViT（Vision Transformer）为什么需要固定尺寸输入？

VLM 的视觉编码器通常是 **Vision Transformer（ViT）**。ViT 的工作原理是：

```
原始图像 (H × W 像素)
    ↓ 切分
N 个小方块 (Patch)，每个 patch = P×P 像素
    ↓ 每个 patch 拉平成向量
N 个向量 (= H×W / P² 个)
    ↓ 加入位置编码（Positional Embedding）
    ↓ 送入 Transformer 编码器
N 个视觉 Token
```

问题出在**位置编码**上。ViT 在预训练时，使用的是**绝对位置嵌入（Absolute Positional Embedding, APE）**——就是说，位置 1 的 patch、位置 2 的 patch……每个位置都有一个固定的、专属的向量。

这意味着：**位置编码表的长度是在训练时就固定下来的！**

比如，用 224×224 图像、Patch Size=16 训练的 ViT：
- N = (224/16)² = 14×14 = **196 个位置**
- 位置编码表就只有 196 行
- 如果推理时输入 336×336 的图像，N = 441 个位置，位置编码表**根本没有对应的行**！

所以 绝大多数 VLM 中的视觉编码器（如 CLIP 等）都以固定分辨率感知图像，例如 336×336 像素。

#### 0.3 强行缩放会带来哪些具体损害？

假设你有一张 1920×1080 的发票截图，里面有很多小字。现在要把它压缩到 336×336：

```
原始: 1920×1080 = 207万像素
压缩后: 336×336 = 11万像素
压缩比: 约 19:1 ！！！

原来一个 "¥" 字符可能占据 20×20 像素
压缩后只剩 1×1 像素——完全无法识别！
```

更糟糕的是，1920×1080 是 16:9 的横向宽图，336×336 是正方形：

```
原始宽高比 16:9 → 强制变成 1:1
图像被横向压缩了 (1920/1080 ÷ 1 = 1.78 倍)
所有文字都变"胖"了，人脸变宽，表格列距变短
```

文档或表格被扭曲成正方形后会变得更难阅读：列对齐偏移、文字宽高比改变、表格结构变得模糊。

对于需要处理商业文档、发票或结构化报告的 VLM 来说，原生分辨率处理是一种**正确性要求**，而不仅仅是质量提升。

#### 0.4 "分辨率困境"——问题的双重性

现在我们能精确地描述这个困境了，它有**两个相互矛盾的方向**：

| 方向 | 问题描述 |
|------|---------|
| **分辨率太低** | 信息损失严重，OCR 失败，细节丢失，宽高比变形 |
| **分辨率太高** | Token 数量爆炸，计算成本和内存急剧增加，推理速度极慢 |

提升输入图像分辨率对于增强 VLM 性能至关重要，尤其在文本密集型图像理解任务上。然而，ViT 等流行视觉编码器在高分辨率下效率低下，因为大量 Token 数量和高编码延迟使其面临严峻挑战。

无论是单次高分辨率处理还是多张低分辨率 Tile 策略，对高分辨率图像推理都会增加计算成本和视觉 Token 生成延迟。此外，高分辨率图像产生更多 Token，导致 LLM 的预填充时间（prefilling time）和首 Token 延迟（TTFT）增加。

---

### 🏛️ 第一章：固定分辨率时代（2021—2023）——奠基与局限

#### 1.1 CLIP 的诞生与"224 的魔咒"（2021）

2021 年，OpenAI 发布了 **CLIP（Contrastive Language-Image Pre-Training）**，它用 4 亿图文对做对比学习预训练，第一次实现了高质量的图文语义对齐。

CLIP 的 ViT-L/14 变体在预训练时使用 **224×224** 像素的固定输入。这是一个在当时计算资源下合理的工程选择：
- 224 × 224 / 14² ≈ 256 个 Patch，计算量可控
- 图文对比学习任务本身对细节要求不高（判断"这张图是猫"，不需要认清图里的小字）

但这个选择为后来所有基于 CLIP 的 VLM 埋下了"固定分辨率"的伏笔。

#### 1.2 LLaVA 1.0 到 1.5——224 升级到 336，但本质未变（2023）

2023 年，LLaVA 系列模型将 CLIP 视觉编码器接上 LLM，开创了 VLM 的流行范式。

LLaVA 采用 CLIP 风格的预处理，将图像缩放并中心裁剪到固定方形分辨率（如 224-336 px），用 CLIP ViT 编码器提取 Patch 嵌入，再通过轻量级两层 MLP 投影器将其映射到 LLM 的词嵌入空间。这种简单的连接器使得视觉-语言接口的端到端训练非常高效。

与原始 LLaVA 相比，LLaVA-1.5 将输入图像分辨率从 224 提升到 336，并加入了更多指令微调数据，带来了显著的性能提升。

这是一种**静态提升策略**：把整个 ViT 做位置插值（Position Interpolation），让 196 个位置扩展到 441 个位置（336×336 / 14²）。

```
CLIP ViT-L 224px → 位置插值 → CLIP ViT-L 336px
- 原始位置编码: 196 个向量
- 插值后: 441 个向量（在原 196 个点之间"插值"出新的点）
- 在新分辨率数据上微调几步，让模型适应
```

使用 ViT 作为视觉编码器时，为了提升分辨率，以往的方法主要进行位置嵌入插值并在新分辨率上微调 ViT 骨干网络。然而，这通常需要在大规模图文数据集上微调，且将推理时的图像分辨率限制在固定大小。

**固定分辨率时代的本质局限：**

固定分辨率方法（如 LLaVA-1.5 和 PaliGemma）先将输入图像缩放到固定尺寸（如 336×336）再进行 VLM 编码。尽管其计算效率高、结构简单，但这类方法的表示往往难以充分捕捉复杂、信息密集图像中的细粒度细节。

MLLM 的视觉编码器正在逐渐从复用固定分辨率主干网络向原生分辨率建模转变。传统固定分辨率 ViT 通常为对比性图像-文本匹配而预训练，其粗粒度表示往往不足以满足对细节敏感的下游任务需求，如 OCR、细粒度识别、文档理解和视频理解。

---

### ✂️ 第二章：裁剪/切块策略（Cropping-Based）时代（2024）——"分而治之"的工程学

#### 2.1 核心思路：不动编码器，动预处理

既然 ViT 只能接受固定尺寸输入，那就想办法"欺骗"它：**把一张大图切成多个小图，每个小图都恰好是 ViT 能接受的尺寸，分别编码后拼接 Token。**

这类方法统称为 **Tiling（切片/切块）** 或 **Cropping-Based** 方法。

#### 2.2 LLaVA-NeXT 的 AnyRes（2024 年初）

（注：AnyRes 已在上一轮回复中详细讲解，此处聚焦其在技术发展脉络中的位置）

LLaVA-NeXT（也叫 LLaVA-1.6）在 LLaVA-1.5 基础上进一步提升输入图像分辨率，改善了推理、OCR 和知识理解能力。与 LLaVA-1.5 的固定分辨率提升不同，LLaVA-NeXT 采用了动态高分辨率设计——模型可以根据输入图像分辨率选择最佳宽高比，最高可将分辨率提升 4 倍。在不改变视觉编码器的情况下，高分辨率图像被拆分为多个与原始编码器输入尺寸相同的子图，分别编码后拼接送入 LLM。

#### 2.3 InternXComposer2-4KHD——4K 分辨率探索（2024）

InternLM-XComposer2-4KHD 在实践中采用 OpenAI CLIP ViT-L-14-336 作为视觉编码器。ViT 的处理分辨率保持 336×336，同时采用动态 Patch 配置来处理更高分辨率的图像。预训练时使用"HD-25"配置，将输入图像随机缩放到更大的分辨率以生成更多 Patch，限制条件是 Patch 总数不超过 25 个。

该方法支持从 336 像素一直到 4K 分辨率的处理，最大分辨率超过了此前方法（如 Monkey 的 1.5K 和 UReader 的 1.2K）。

#### 2.4 InternVL2——大规模工程化 Tiling（2024）

InternVL 引入了通过自适应切片实现动态高分辨率处理的机制。图像被分割为数量可变的 448×448 Tile（从单个 Tile 到数十个 Tile 不等，支持最高 4K 输入），每个 Tile 由 InternViT-6B 编码。得到的视觉特征送入基于 PixelShuffle 的轻量级下采样层以缩减空间维度，再与文本 Token 拼接，由 LLM 联合处理。这种动态切片策略使得细粒度文本识别和高分辨率文档、技术图像的精细结构理解成为可能。

采用基于 Tile 的方法，图像被分割为动态数量的 448×448 像素 Tile，加上一张将完整图像缩放到 448×448 的全局缩略图，帮助模型捕捉整体图像信息。以 Qianfan-VL 为例，各模型最多支持 12 个 Tile。

#### 2.5 Cropping 方法的系统性问题

随着 Tiling 方法被大规模应用，研究者开始发现并量化其系统性缺陷：

Tiling 方式虽然有效，但可能破坏图像的全局结构，并引入冗余计算。

切片策略将高分辨率图像分割成更小的、可管理的区域分别处理，但这种方法会丢失跨 Tile 的上下文信息，并可能在 Tile 边界处切断对象，可能错失不同 Tile 中对象之间的关联，或将大型对象碎片化。

动态分辨率方法通过自适应图像裁剪或原生分辨率编码来增强细粒度视觉信息的表示，但这些方法往往面临"分辨率困境"——视觉 Token 数量高度可变且过多，会带来显著的索引存储和计算开销。

用一张图来理解 Tiling 的 Token 爆炸问题：

```
LLaVA-1.5（固定）:  1 张图 → 576 个 Token
LLaVA-NeXT（4 Tile）:  1 张图 → 4×576 + 576 = 2880 个 Token  （5倍！）
InternVL2（36 Tile）: 1 张图 → 36×256 = 9216 个 Token  （16倍！）

一般 LLM 的文本上下文: 4096 个 Token
一张高分辨率图的视觉 Token: 已经超过整个文本上下文长度！
```

动态分辨率方法给移动端部署带来了特殊挑战：图像 Patch 数量的增多会大幅拖慢视觉编码器，而产生的更长图像 Token 序列则导致语言模型推理延迟显著增加。

---

### 🔀 第三章：混合编码器策略（Hybrid-Resolution）——双编码器的"高低配"

#### 3.1 思路：让高、低分辨率编码器各司其职

这一类方法不再依赖单一编码器，而是同时使用**两个编码器**：
- 一个**低分辨率编码器**：负责理解全局语义（"图里有什么"）
- 一个**高分辨率编码器**：负责捕捉局部细节（"图里的文字是什么"）

混合分辨率方法采用双编码器策略，将高分辨率编码器（关注局部细节）与低分辨率编码器（把握全局语境）相结合。

#### 3.2 代表模型：CogAgent、Mini-Gemini（Vary）

为了增强高分辨率理解，一些方法采用了高分辨率（HR）视觉编码器或专门为高、低分辨率输入设计的双编码器。例如，Vary 引入了一个支持高分辨率输入的新图像编码器，其特征与原始 CLIP 视觉编码器的低分辨率嵌入拼接在一起；CogAgent 和 Mini-Gemini 也都采用独立的视觉编码器分别处理高、低分辨率图像，并通过交叉注意力模块融合特征。

#### 3.3 混合策略的工程结构示意

```
输入图像 (任意尺寸)
    ├── 缩放到 336×336 → 低分辨率编码器 (CLIP ViT) → 全局语义 Token
    └── 切割/高分辨率 → 高分辨率编码器 (SAM/ConvNeXt) → 局部细节 Token
                                ↓
                    交叉注意力 / 特征融合
                                ↓
                     合并的视觉表示 → LLM
```

#### 3.4 混合策略的优缺点

**优点：**
- ✅ 同时获得全局理解和局部细节
- ✅ 低分辨率分支使用预训练 CLIP，不用从头训练

**缺点：**
- ❌ 参数量翻倍（两个编码器）
- ❌ 推理时需要跑两次编码器，延迟更高
- ❌ 两个编码器的特征空间不同，融合本身需要额外设计

高分辨率视觉编码器通过引入更强的视觉主干（如 SAM、ConvNeXt）或交叉注意力、适配器等架构改动来提升感知能力，但这些方法通常需要大量架构修改和额外训练。

---

### 🌿 第四章：原生分辨率时代（2024—2025）——让编码器"天生"支持任意尺寸

#### 4.1 什么是原生分辨率（Native Resolution）？

前面三章的所有方法，本质上都是在**绕过**视觉编码器的固定尺寸限制：要么强行缩放，要么切块分批，要么用多个编码器拼凑。

而**原生分辨率**的思想是：**从根本上改造编码器，让它直接支持任意形状和尺寸的图像输入，不需要任何预处理**。

这意味着：
- 不需要 Padding（填充）到固定尺寸
- 不需要 Resizing（缩放）变形
- 不需要 Tiling（切块）破坏全局结构
- 宽高比完全保留

采用原生分辨率视觉编码器的 VLM 已开始涌现，通过保留图像的原始分辨率和宽高比，提供了一条全新的技术路径。

#### 4.2 关键基础技术一：NaViT（Patch n' Pack，2023）

NaViT 是 Google 提出的原生分辨率 ViT 训练方案，包含两个核心思想：

##### 思想 A：因式分解的位置编码（Factored Positional Embedding）

NaViT 不再使用单一的绝对位置编码，而是将位置拆分为**行位置 + 列位置**：

```
传统 APE: 每个 Patch 有一个全局位置 ID (1, 2, 3, ..., N)
NaViT:  每个 Patch 有两个独立 ID:
         行位置 ID (0, 0, 0, 1, 1, 1, ...)  → 分配给高度
         列位置 ID (0, 1, 2, 0, 1, 2, ...)  → 分配给宽度
```

这样，位置编码就不再依赖图像的总宽度，**任意高度×宽度的图像都能正确编码**。

##### 思想 B：Patch Packing（Patch 打包）

NaViT 的训练不是一次处理一张图，而是把**多张不同尺寸的图的 Patch 一起塞进同一个 Sequence**，用 Attention Mask 区分哪些 Patch 属于哪张图：

```
传统 ViT 训练 Batch:
  图1: [P1 P2 P3 ... P196] 填充 PAD PAD ...  ← 大量浪费
  图2: [P1 P2 P3 ... P441] 填充 PAD PAD ...

NaViT Patch Packing:
  Sequence: [图1-P1 图1-P2 ... 图1-P100 | 图2-P1 图2-P2 ... 图2-P124 | 图3-P1 ...]
  Mask:     [1      1      ...  1        | 2      2      ...  2        | 3      ...]
  ← 填满整个 Sequence 长度，几乎没有浪费！
```

这极大地提升了训练效率，并使模型在各种分辨率下都得到充分训练。

#### 4.3 关键基础技术二：FlexiViT（2022—2023）

FlexiViT 解决的是另一个问题：**让单一模型支持多种 Token 数量（即多种分辨率级别）**。

传统做法是每个分辨率训练一个独立的 ViT Checkpoint（336×336 一个，448×448 一个）；FlexiViT 则用**随机 Patch Size 训练**，让模型见到过各种各样的 Patch 数量，形成"分辨率无关"的鲁棒性。

#### 4.4 原生分辨率的集大成者：NaFlex（SigLIP 2，2025 年 2 月）

NaFlex 将 NaViT 和 FlexiViT 的思想完美融合：
- **来自 NaViT**：保持原生宽高比，因式分解位置编码，不做强制正方形
- **来自 FlexiViT**：支持多种 Token 预算（max_num_patches），单一模型适配所有

（NaFlex 已在上一轮回复中详细讲解，此处不再重复）

#### 4.5 另一条路：Qwen2-VL 的 Native Dynamic Resolution + 2D RoPE

与前代不同，Qwen2-VL 能处理任意分辨率的图像，并动态将其转换为数量可变的视觉 Token。为支持这一特性，研究者对 ViT 进行了修改：移除了原有的绝对位置嵌入，引入 2D-RoPE 来捕捉图像的二维位置信息。

在推理阶段，不同分辨率的图像被打包进同一个序列，序列总长度受控以限制 GPU 内存使用。为减少每张图像的视觉 Token 数量，ViT 之后使用一个简单的 MLP 层将相邻的 2×2 个 Token 压缩成单个 Token。最终，一张 224×224、patch_size=14 的图像在进入 LLM 前会被压缩为 66 个 Token。

#### 4.6 Seed1.5-VL 的 Seed-ViT——从头构建原生分辨率编码器

针对固定分辨率处理带来的挑战，ByteDance 开发了 Seed-ViT，这是一个专为原生分辨率特征提取而设计的视觉编码器。它基于成熟的 ViT 架构，拥有 5.32 亿参数。该编码器在各类通用视觉感知领域表现出色——值得注意的是，在零样本分类基准上，Seed-ViT 达到了参数量大得多的 InternVL-C（60 亿参数）的相当水平，体现了其高效性。

该视觉编码器原生支持动态图像分辨率，并采用 2D RoPE 进行位置编码，能够灵活适应任意尺寸的图像。为提升计算效率，架构在相邻的 2×2 特征 Patch 上应用平均池化；随后两层 MLP 对池化后的特征进行处理，再送入 LLM。

### 🗜️ 第五章：视觉 Token 压缩——解决 Token 爆炸的第五条路

动态分辨率带来了 Token 数量暴增的问题，研究者从另一个维度入手：**压缩掉冗余的视觉 Token**。

#### 5.1 为什么视觉 Token 可以被大量压缩？

与文本相比，图像信息往往具有更高的冗余度，这使得视觉 Token 压缩在 VLM 中更加合理且有效。

直觉上很好理解：一张蓝天白云的图片，天空区域有几百个 Patch，它们几乎是完全相同的蓝色——这些 Patch 对应的 Token 携带的信息几乎一样，99% 是冗余的。

近期多模态方法通过选取视觉上最显著的 Token、保留与文本相关的区域、压缩视觉信息流或推理时估计 Token 敏感性等方式，将这些思路适配到 VLM 管线中。这些方法表明，视觉冗余是相当显著的，紧凑的 Token 集合可以在保留大部分多模态能力的同时大幅减少开销。

#### 5.2 按压缩位置分类：三个维度

这些方法在架构上的主要区别在于压缩发生的位置：一些方法在视觉编码器内部操作，另一些在视觉编码器与 LLM 主干之间（通常称为 Pre-LLM 压缩），还有一些在 LLM 主干内部进行剪枝（通常称为 Inner-LLM 剪枝）。

```
┌──────────────────────────────────────────────────────────────────┐
│  输入图像                                                         │
│    ↓                                                             │
│  [视觉编码器 ViT]                                                 │
│    ↓ ← ① 编码器内压缩（Early Compression）                        │
│  视觉 Token 序列 (N 个)                                           │
│    ↓ ← ② Pre-LLM 压缩（投影层/连接器层）                          │
│  压缩后 Token (M 个, M << N)                                      │
│    ↓                                                             │
│  [LLM 层 1]  ← ③ Inner-LLM 剪枝                                  │
│  [LLM 层 2]  ← ③ Inner-LLM 剪枝                                  │
│  ...                                                             │
└──────────────────────────────────────────────────────────────────┘
```

#### 5.3 按压缩方式分类：四大流派

视觉 Token 压缩方法可分为四大类：(1) **剪枝（Pruning）**——移除冗余 Token；(2) **池化（Pooling）**——聚合局部特征；(3) **卷积（Convolution）**——学习下采样；(4) **重采样器（Resampler）**——通过交叉注意力重新分配 Token。

下面逐类介绍：

##### 流派一：Pruning 剪枝——"扔掉没用的"

核心逻辑：给每个视觉 Token 评一个重要性分数，把分数低的直接扔掉。

**FastV（2024）**——最早探索 VLM 视觉 Token 压缩的方法：
FastV 是首个探索 MLLM 视觉 Token 压缩的方法，基于 Token 的平均注意力分数剪枝冗余 Token。

**LLaVA-PruMerge（2024）**：
LLaVA-PruMerge 提出了一种自适应选择策略，利用 CLS Token 与视觉 Token 之间注意力的稀疏性。它选出注意力高的 Token，再基于 Key 的相似性对其聚类合并，以提升信息密度。

**VisionZip（2024）**：
VisionZip 首先识别出具有强注意力信号的"主导 Token"，并进一步基于相似性对其合并，确保同时保留显著且上下文丰富的 Token。这些方法显著减小了 LLM 的输入规模，同时保持了具有竞争力的性能。

**最前沿的压缩效果：**
在极端压缩设置下（仅保留 64 个视觉 Token，压缩率达 88.9%），部分方法仍能保持完整 Token 性能的 95.73%，体现出强大的高效性与极低的性能损耗。

##### 流派二：Pooling 池化——"把附近的合并"

最典型的就是 **Pixel Unshuffle / PixelShuffle**（在 InternVL 中被广泛使用）和**平均池化**（在 Qwen2-VL、Seed-ViT 中使用）：

Qwen2-VL 在 ViT 之后使用一个简单的 MLP 层将相邻的 2×2 个 Token 压缩成单个 Token。最终，一张 224×224、patch_size=14 的图像在进入 LLM 前会被压缩为 66 个 Token。

这是一种**无需学习**的固定池化：4 个相邻 Token → 1 个 Token，Token 数量变为原来的 1/4。

##### 流派三：Resampler 重采样器——"用 Q-Former 压缩"

这是 BLIP-2 开创的路线：用一组**可学习的 Query 向量**，通过交叉注意力从视觉 Token 中"抽取"固定数量的语义摘要：

```
N 个视觉 Token（可变，来自 ViT）
    ↓  交叉注意力
M 个可学习 Query（固定，如 32 个）
    ↓
M 个压缩后的视觉 Token → LLM
```

Q-Former 通过训练跨模态模块，将数百个视觉 Token 压缩成一小组可学习 Token，从而降低视觉 Token 冗余。

**优点**：输出 Token 数量完全固定，对 LLM 非常友好。
**缺点**：固定 Query 数量可能导致细节信息丢失，训练难度较高。

##### 流派四：文本引导的智能压缩——"按需保留"

上面三类方法有一个共同缺陷：**不知道用户在问什么，盲目压缩**。

如果用户问"图中的电话号码是什么"，那电话号码所在区域的 Token 绝对不该被删掉；但如果问"图中背景是什么颜色"，背景 Token 才重要。

ATP-LLaVA 在 VLM 中引入可训练模块，基于文本-视觉和视觉-视觉注意力的重要性分数来剪枝视觉 Token。

这代表了压缩技术的最新方向：**文本感知（Text-Aware）的条件性视觉 Token 压缩**。

### 📊 第六章：技术全景图与横向对比

#### 6.1 五大策略的完整对比

| 策略 | 代表模型 | 核心机制 | 宽高比 | Token数量 | 修改编码器 | 主要缺点 |
|------|---------|---------|--------|-----------|-----------|---------|
| **固定分辨率** | LLaVA-1.5, PaliGemma | 强制缩放+位置插值 | ❌变形 | 固定（少） | 否 | 信息损失，形变 |
| **Cropping/Tiling** | LLaVA-NeXT, InternVL | 切块分别编码 | ✅近似保持 | 大量增加 | 否 | Token爆炸，割裂全局 |
| **Hybrid双编码器** | CogAgent, Mini-Gemini | 高+低分辨率并行 | ⚠️部分保持 | 增加 | 部分 | 参数/延迟翻倍 |
| **原生分辨率** | Qwen2-VL, NaFlex | 从头训练NaViT式编码器 | ✅完美保持 | 灵活可控 | ✅完全重构 | 需要大量预训练 |
| **Token压缩** | FastV, VisionZip | 剪枝/池化/重采样 | 取决于前级 | 大量减少 | 否（后处理） | 信息可能损失 |

#### 6.2 从研究结论看各策略的优劣

在受限的训练数据条件下，原生分辨率策略在准确率上显著优于基于裁剪的方法。此外，它对区域级别变化和宽高比变化表现出更强的鲁棒性。在所有指标上，原生分辨率策略均一致地超越了裁剪方法和固定分辨率策略。

#### 6.3 实用选型指南

```
你的场景是什么？

① 快速原型 / 资源有限
   → 固定分辨率（LLaVA-1.5 风格）
   简单、快速、资源少

② 需要高分辨率 / 不想重训编码器
   → Tiling + AnyRes（LLaVA-NeXT / InternVL 风格）
   不改编码器，性能显著提升，Token多但可接受

③ 需要超高分辨率 + 资源充足
   → Hybrid双编码器（Mini-Gemini风格）
   全局+局部兼顾，但两倍开销

④ 追求最优质量 / 有大规模预训练资源
   → 原生分辨率（Qwen2-VL / NaFlex风格）
   最佳宽高比保持，最少信息损失

⑤ 需要在 ② ④ 基础上降低推理延迟
   → 加入 Token 压缩（FastV / VisionZip / Q-Former）
   根据任务需求，在质量和速度之间找平衡
```

### 🚀 第七章：最前沿技术与未来趋势（2025—）

#### 7.1 当前最前沿的技术组合

目前 2025 年最先进的 VLM 普遍采用以下技术组合：

```
【最强组合公式】

原生分辨率 ViT（NaViT/Seed-ViT）
    + 2D/M-RoPE 位置编码
    + 视频预训练（空间+时序联合建模）
    + 自适应 Token 压缩（2×2 池化 或 智能剪枝）
    + 多分辨率课程训练（从低到高逐渐提升分辨率）
```

许多近期的 VLM 通过架构创新原生支持动态分辨率，例如 Qwen2-VL 的 2D RoPE、MiniCPM 的高效高分辨率处理、LLaVA-UHD 的可变宽高比处理，但这些方法通常需要大量预训练。

#### 7.2 Keye-VL 2.0——原生分辨率的最新进展（2025 年中）

高分辨率输入主要有两条探索路径。动态切片方法（如 InternVL3 和 MiniCPM-V）将大图切成较小的裁剪块再送入固定分辨率编码器。这种方式虽然有效，但可能破坏全局结构并引入冗余计算。

原生分辨率方法（如 NaViT、Qwen3.5 和 K2.5）则直接在原始分辨率下处理图像，代表了当前最前沿的技术方向。

#### 7.3 多分辨率层次编码——MURE（2025）

新兴的多分辨率编码范式通过多次采样（如 4 种不同分辨率）生成从粗到细的综合表示，同时在推理时保持固定的视觉 Token 数量。

这是一种很有趣的思路：不在一个分辨率上"押宝"，而是同时编码多个分辨率，让模型自己选择从哪个尺度取信息——类似于人眼在看图时会自动切换远看（全局）和近看（细节）的模式。

#### 7.4 任务感知分辨率优化（Task-Aware Resolution）

虽然原生动态分辨率模型提供了极大的灵活性，但它们通常需要大量预训练且不会针对单个任务显式优化最优分辨率。一个新兴方向是对现有 VLM 进行轻量级的事后适配，自动为每个具体任务找到最佳的输入分辨率。

#### 7.5 编解码器引导的 Patch 采样（Codec-based Patch Sampling）

基于编解码器的 Patch 采样在严格受控的 Token 预算下评估"编解码引导的切片化"原则：对于每段测试视频，均匀采样 64 帧以覆盖完整的时间跨度。

这是一个新方向：借鉴视频压缩编解码的思路，利用编码码率来衡量图像区域的信息密度，优先保留高码率（高信息量）的区域对应的 Token。
