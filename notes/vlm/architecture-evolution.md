# VLM 融合对齐的架构演进：从 CLIP 到 LLaVA 与原生多模态

> 以「怎样把视觉信息融合进语言模型」为主线，梳理 VLM 的架构演进：从双塔对比的 CLIP、引入 cross-attention 的 ALBEF / BLIP、用 Q-Former 做桥梁的 BLIP-2、极简投影的 LLaVA，一直到端到端的原生多模态，并给出各条路线的优缺点与当前社区共识。

## 总览
问题：多模态最大的难点在于视觉信息和文本信息向量化后维度不同、语义表示也不同，因此难以相互理解。
主要解决思路：如果从头训练，将图像编码器与文本编码器接在融合编码器之上，由于图像维度较高、分到更多的比重会更好。如果不从头训练，将图像编码器的输出结果经过融合编码器变换，输入到文本编码器中，从而借助LLM强大的理解能力。
各大模型架构的区别点：
1. 怎样融合：cross-attention，Q-Former查询式提取，直接投影，端到端从头训练实现原生多模态。
2. 是否借助已有模型
3. 训练时冻结哪些部分
4. 数据：已有数据，机器合成数据

## 融合对齐
### 一开始设想的幼稚方法：直接拼接后做self-attention
缺陷：图像和文本的交互方式应该不同，但这里完全一视同仁，没有区分模态的先验知识。计算量大。
### 双塔并行，最后只计算相似度来对齐：CLIP
#### 优点
- **革命性的零样本能力**：不用微调就能做分类
- **强大的表征**：学到的特征非常通用
- **规模化成功**：证明了大规模图文对比学习的可行性
#### 缺点
- **只能做检索/分类**：无法生成文本描述
- **无深层交互**：图像和文本编码完全独立，只在最后算相似度
- **细粒度理解弱**：CLS token压缩了所有信息，丢失空间细节
### 对齐后利用Cross-Attention融合：ALBEF和BLIP
ALBEF在CLIP基础上扩大了融合编码器规模，把它变成了多模态文本编码器（借助cross attention实现图像信息的输入）。ALBEF是典型的对齐后融合的设计。BLIP多模态编码器部分增加了与encoder并行的decoder模块以统一理解和生成，加入模型生成数据与真实数据对比选择更优的从而实现数据质量优化。
**BLIP标志着"自己训练一切"的路线接近极限——语言模型需要更大规模才能更强，但视觉语言联合训练成本太高。** 自己训练的解码器不如专门的LLM。
### 从自己训练向借助已有的过渡：Flamingo
既有桥接模型，又有cross-attention。
#### 优点

- **范式转变**：首次成功将预训练LLM与视觉结合
- **Few-shot能力**：和GPT-3一样，可以通过示例学习新任务
- **多图/视频支持**：架构天然支持多图输入
- **参数高效**：只需训练约1.6B参数（vs 80B的Chinchilla）

#### 缺点

- **需要修改LLM结构**：插入层需要改变模型架构，不够通用
- **依赖特定LLM**：Chinchilla不开源，难以复现
- **推理复杂**：Cross-Attention层增加了推理开销

**Flamingo的核心贡献：证明了"冻结大模型+轻量适配"的路线可行，为后续BLIP-2和LLaVA奠定基础。**
### Q-Former：BLIP-2
第一阶段ITC进行对齐，相比BLIP，因为训练参数很小，扩大了batch size从而不必用对比学习的MOCO方法而去掉了作为教师网络的动量模型。
#### 优点

- **极致的参数效率**：只需训练188M参数，就能利用数十B的LLM
- **LLM无关**：可以即插即用各种LLM（OPT、FlanT5、LLaMA...）
- **Q-Former设计优雅**：32个Query像"记者团"一样采访图像
- **推理高效**：只有32个visual tokens进入LLM

#### 缺点

- **信息瓶颈**：257个tokens压缩到32个，必然丢失细节
- **两阶段训练复杂**：需要先训练Q-Former再连接LLM
- **空间理解弱**：压缩后难以保留精确的空间位置信息
- **对OCR等细粒度任务效果有限**
### 投影：LLaVA
最简单的方法，但是性能卓越。
BLIP-2 的思路："LLM是冻结的，我需要一个复杂的翻译器把视觉信息完美转换成LLM能懂的"
LLaVA的思路："CLIP已经学到了和语言对齐的视觉表示，LLM足够强大可以自己学会理解"
#### 优点

- **极度简单**：架构简单到令人惊讶，几行代码就能实现
- **效果优秀**：在多个benchmark上超越了复杂得多的BLIP-2
- **易于复现**：训练成本低，社区迅速跟进
- **指令数据创新**：用GPT-4生成数据的方法被广泛采用

#### 缺点

- **Token数量多**：576个tokens增加了推理成本
- **依赖CLIP**：视觉编码器的能力是上限
- **分辨率受限**：336×336可能不够精细任务

## 目前的发展
```text
实践证明：

1. 简单投影 + 强大LLM + 高质量数据 = 最佳性价比
   → LLaVA路线成为主流，让LLM自己去学，连接器趋于简化

2. 动态分辨率成为标配
   → Qwen2-VL, LLaVA-NeXT 都支持

3. Q-Former路线逐渐式微
   → 压缩太狠丢信息，不如直接用更长context

4. 原生多模态是终极形态
   → 但只有Google/OpenAI等大厂能做
   
5. 数据质量更加重要，高质量指令数据的边际收益最高
```
