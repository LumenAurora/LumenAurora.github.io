# 后训练技术谱系

> 本文梳理后训练的技术谱系（SFT、RLHF、RLVR、蒸馏与损失设计），并以 Search-R1 中发现的 GRPO 坍塌现象为例，讲解其背后的「惰性似然位移（LLD）」机制，以及对应的似然保持正则化（LLDS）解法。核心参考：Deng et al., 《On GRPO Collapse in Search-R1: The Lazy Likelihood-Displacement Death Spiral》, arXiv:2512.04220 (2025)。

后训练pipeline，SFT、RLHF、RLVR、蒸馏，损失设计。
## 算法的分析
### GRPO
这个问题问到了**研究品味**和**洞察力**的核心。作者能想到这一点，不是靠运气，而是基于对GRPO数学本质的深刻直觉。

这种直觉可以概括为：**GRPO本质上是一个“组内相对比较”的算法，而语言模型的梯度具有“可加性”和“干扰性”。当这两者在“工具调用”这个特殊场景下碰撞时，LLD的发现是必然的。**

以下是该发现背后的逻辑必然性链条：

#### 1. 直觉第一跳：GRPO的“零和博弈”本质
如果你深入看GRPO的损失函数，你会发现它的优势（Advantage）是组内归一化的：`A = (r_i - mean) / std`。这意味着**在一组样本里，有正优势（好回答）就必然有负优势（坏回答），且所有优势之和严格等于0**。

- **作者的直觉**：这不是“各自奔向幸福”的绝对优化（像PPO那样有绝对值基线），而是一场**“组内拔河”**。正梯度想把概率往上拉，负梯度想把概率往下推。
- **由此产生的反问**：既然是拔河，谁赢了？如果正负样本数量不均等（比如只有1个好回答，7个坏回答），负梯度的**数量优势**是不是会把正梯度淹没？——这就产生了对“梯度冲突”的第一层警觉。

#### 2. 直觉第二跳：为什么“工具场景”把这个拔河放大到了极致？
作者之前肯定跑过纯文本（非工具）的GRPO，发现坍塌不明显。但在工具场景（Search-R1）里，崩溃太普遍了。

- **作者的观察**：在工具场景下，正确轨迹和错误轨迹的前半段经常**一模一样**（都发出同样的搜索词`<search>NRL grand final winner</search>`），差异仅在于最后的`<answer>`标签里的那个词。
- **数学直觉（神经正切核 NTK 理论）**：在深度学习中，两个输入（上下文）极其相似的样本，它们的**梯度方向在高维空间中几乎是平行的**。
- **推导出的结论**：好样本（正确回答）和坏样本（错误回答）的梯度方向高度对齐，但**方向完全相反**（一个要加概率，一个要减概率）。这就好比两个人站在同一条直线上往相反方向拉一根绳子，力量互相抵消。结果就是：**错误样本的负梯度，会以极大的效率抵消掉正确样本的正梯度。** 这个洞察，是前人完全没有捕捉到的。

#### 3. 直觉第三跳：既然力量抵消，为什么是“正确”的在往下掉，而不是“错误”的在往上涨？
如果正负梯度相互抵消，按理说应该是两败俱伤，或者训练震荡。但作者发现结果是**明确地坍缩**。

- **作者的关键追问**：当模型看到一个“几乎正确但最终答错”的样本时，模型会怎么想？由于这个样本的前半段概率很高，但最终奖励是0（负优势），GRPO会狠狠惩罚这整个序列。
- **惩罚的效果**：因为前半段概率太高了（接近1），惩罚梯度会把前半段所有token的概率都**暴力往下拉**。
- **残酷的现实**：而那个唯一正确的样本，它的前半段恰好和这个错误样本一模一样。于是，**惩罚错误样本的“子弹出膛”，正中正确样本的“眉心”**。正确样本被“误伤”了，导致它的似然（Likelihood）非但没涨，反而跌了。
- **这就是LLD（惰性似然位移）诞生的第一缕火光**：作者意识到，训练坍塌不是源于“模型不会回答”，而是源于“**模型因为害怕犯错，连正确的路都不敢走了**”。

#### 4. 直觉第四跳：为什么前人没发现？因为他们只看了最终Loss
前人的归因停留在“错误样本概率太低导致重要性权重爆炸”。作者觉得这不合理，因为如果是这样，那正确样本的概率总该涨吧？

- **作者的直觉转变**：与其盯着错误样本看，不如**盯着正确样本看**。
- **实验验证（图3a）**：作者专门抽取出只有**正确轨迹**的似然来画图，发现它居然在**单调递减**。这个反直觉的现象暴露了GRPO的致命缺陷：**GRPO的优化目标在数学上并不等同于“最大化正确轨迹的似然”，它等同于“在组内保持相对优势”**。在相似上下文的拉扯下，GRPO为了惩罚极其相似的错误，被迫牺牲了正确的似然。

#### 5. 直觉第五跳：解法必须“非对称”（Hinge Loss的灵感来源）
既然找到了病根（正确似然被拉低），怎么治？

- **作者的思维推导**：既然我们不能阻止模型惩罚错误（那是它学习的基础），那我们能不能**给正确轨迹加个“护盾”**？
- **为什么选 Action-level + Token-level？**
  - 如果整体锁住正确轨迹（Response-level），模型就学不到新东西（因为完整回答总概率下降一点点但换来其他部分大幅上升，是有益的）。
  - 所以必须**只惩罚那些“导致概率下降的贡献者”**。
- **数学形式的必然性**：正负梯度抵消时，负的贡献往往只集中在少数几个token上（比如那个关键的答案词）。因此，用 `max(0, delta)`（Hinge Loss）——只惩罚变差的部分，不变的部分随便——既保持了梯度的纯净，又避免了过度约束。

---

#### 总结：作者的思维模型（“必然性”训练）

可以把这套思考路径总结为：

> *“GRPO是一个相对算法，它导致正负梯度在参数空间中进行矢量叠加。在工具调用的场景下，正负轨迹的上下文重叠度极高（矢量方向一致），因此叠加表现为‘强对冲’。对冲的结果是，负梯度不仅在惩罚错误，更在物理上排挤了正确轨迹的梯度。既然GRPO无法改变对冲的物理定律，那我就只能**在损失函数层面，切断负梯度流向正确轨迹关键token的通道**——这就是LLDS。”*

**这为什么是顶会级别的直觉？** 因为它把优化算法（GRPO）、数据分布（工具调用的高度共享前缀）和模型架构（Transformer的梯度传播）三者**联动**起来思考，而不是孤立地看其中某一个。这种**系统性**的视角，是普通人看论文永远学不到，但恰恰是顶尖研究者与生俱来的“模型感”。
## Fast-ThinkAct 方法全流程循序渐进讲解

### 一、先搞清楚"这篇论文到底要解决什么问题"

#### 1.1 什么是 VLA（Vision-Language-Action）？

想象你有一个机器人，你对它说：**"把草莓放进抽屉里"**。

机器人需要完成三件事：

| 步骤 | 含义 | 例子 |
|------|------|------|
| **V**ision（看） | 看到当前画面 | 摄像头拍到桌上的草莓和抽屉 |
| **L**anguage（理解指令） | 理解你说的话 | 知道要"放草莓进抽屉" |
| **A**ction（做动作） | 输出具体的机械臂控制指令 | 移动到(0.12, 0.34)，抓取，放入… |

#### 1.2 为什么需要"推理"（Reasoning）？

普通的 VLA 模型只会"模仿"——训练数据里有什么就做什么。遇到没见过的情况就懵了，比如：
- 需要多步骤规划的长任务
- 任务执行失败后需要自我纠正
- 面对全新场景需要灵活适应

**解决方案**：让模型先"想一想"再行动，就像人做数学题要写过程一样，这就是 **Chain-of-Thought（CoT，思维链）**。

#### 1.3 但是！"想太多"会太慢！

之前的方法（如 ThinkAct）让模型生成 **~250个文本token** 的推理过程，比如：

> "首先我需要找到草莓的位置，草莓在图片左上方，抽屉在右下方，我需要先移动机械臂到草莓上方，然后张开夹爪，向下移动抓住草莓，然后移动到抽屉位置……"

这会导致：
- 每次决策需要 **好几秒**（~0.1 Hz）
- 但机器人需要 **1-15 Hz** 的实时控制频率

> 🎯 **核心矛盾**：推理能提升性能，但推理太慢，机器人等不起！

---

### 二、Fast-ThinkAct 的核心思路（一句话版本）

> **把 250 个文本 token 的推理过程，压缩成 6 个"连续向量"（latent tokens），既保留了推理能力，又快了 9.3 倍！**

```
之前的方法：  "把草莓放进抽屉" → [250个文字推理] → 动作
                    （慢！好几秒）

Fast-ThinkAct：  "把草莓放进抽屉" → [6个连续向量] → 动作
                    （快！只要805ms）
```

- **目的**：让模型学会"先想再答"的模式

> 🧠 **类比**：这就像先让学生学会基础知识（SFT），再教他做题要写步骤（CoT-SFT）。

#### 📌 阶段 2：教师模型训练（GRPO强化学习）

> 目的：训练一个"文本教师"，让它能生成高质量的推理链

##### 什么是GRPO？

GRPO（Group Relative Policy Optimization）是一种强化学习方法。核心思想：

1. 给模型同一个问题，让它生成 **N=5个不同的回答**（rollouts）
2. 用奖励函数给每个回答打分
3. 组内比较：比平均分好的就鼓励，比平均分差的就抑制

**数学公式**：

$$J_{\text{GRPO}}(\theta) = \mathbb{E}_{\tau \sim \mathcal{F}^T_\theta}\left[\min\left(r_\theta(\tau)A(\tau),\ \text{clip}(r_\theta(\tau), 1-\varepsilon, 1+\varepsilon)A(\tau)\right)\right]$$

其中：
- $\tau$ = 一条推理链
- $r_\theta(\tau) = \frac{\mathcal{F}^T_\theta(\tau)}{\mathcal{F}^T_{\text{old}}(\tau)}$ = 新旧策略的概率比（防止更新太猛）
- $A(\tau)$ = 优势函数，衡量这条推理链比组内平均好多少：

$$A(\tau) = \frac{R_\tau - \text{mean}(\{R_i\}_{i \in G(\tau)})}{\text{std}(\{R_i\}_{i \in G(\tau)})}$$

##### 奖励函数是什么？

教师模型使用 **动作对齐的视觉奖励**（来自ThinkAct）：
- 目标完成度奖励
- 轨迹对齐奖励（预测的轨迹和真实轨迹是否吻合）

> 🧠 **类比**：让5个学生做同一道题，做对的加分，做错的减分，逐步让整体水平提高。

##### 关键产出：

训练完成后，教师模型能生成质量参差不齐的推理链。**质量高的记为 $\tau^+$，质量低的记为 $\tau^-$**：

$$\tau^+ = \arg\max_{\tau \in G} A(\tau), \quad \tau^- = \arg\min_{\tau \in G} A(\tau)$$

这些将作为下一步"蒸馏"的偏好对。

---

#### 📌 阶段 3：学生模型训练（核心创新！）

> 目的：把教师的"长篇文字推理"压缩成"6个连续向量"

这是论文最核心的部分，包含 **三个损失函数** 联合训练：

$$\mathcal{L}_{\text{student}} = \mathcal{L}_{\text{verb}} + \mathcal{L}_{\text{distill}} + \mathcal{L}_{\text{ans}}$$

---

##### 🔹 损失1：语言化偏好损失 $\mathcal{L}_{\text{verb}}$（让latent"可说话"）

**问题**：连续向量空间里没有直接的监督信号，怎么知道这6个向量编码了"好的推理"？

**巧妙解法**：引入一个 **语言化器（Verbalizer）** $\mathcal{V}_\psi$，它的任务是：
- 输入：学生生成的6个latent向量 $\mathbf{z} = \{z_m\}_{m=1}^{M}$
- 输出：把这些向量"翻译"成自然语言

然后用 **DPO（Direct Preference Optimization）** 的思想：

$$\mathcal{L}_{\text{verb}} = -\mathbb{E}\left[\log \sigma\left(\beta\left(\log \frac{p_\psi(\tau^+|\mathbf{z})}{p_{\text{ref}}(\tau^+)} - \log \frac{p_\psi(\tau^-|\mathbf{z})}{p_{\text{ref}}(\tau^-)}\right)\right)\right]$$

**翻译成大白话**：
- 让语言化器看到学生的latent后，更倾向于"翻译"出高质量推理 $\tau^+$
- 同时抑制翻译出低质量推理 $\tau^-$ 的可能性
- $\beta=0.1$ 控制偏好强度
- $p_{\text{ref}}$ 是参考模型（没有latent条件输入的语言化器）

**训练细节**：
- 语言化器用 Qwen3-0.6B 初始化，每层插入cross-attention来接收latent
- 前3000次迭代：用标准语言建模损失热身（用 $\tau^+$ 作为ground truth）
- 后1500次迭代：冻结语言化器，切换到 $\mathcal{L}_{\text{verb}}$

> 🧠 **类比**：就像考试时，老师不直接看你的草稿纸（latent），而是让你把思路说出来（语言化），然后判断你说得好不好。如果说出来的是高质量推理，说明你的"内心想法"（latent）是对的。

---

##### 🔹 损失2：视觉规划蒸馏损失 $\mathcal{L}_{\text{distill}}$（让latent包含空间信息）

**问题**：$\mathcal{L}_{\text{verb}}$ 只保证了语言层面的推理质量，但机器人操作还需要 **空间规划能力**（知道往哪里移动）。

**解法**：直接对齐教师和学生在 `<answer>` token 处的隐藏状态：

$$\mathcal{L}_{\text{distill}} = \|h^T_t - h_t\|_2^2$$

其中：
- $h^T_t$ = 教师模型（对应 $\tau^+$）在 `<answer>` token 处的隐藏状态
- $h_t$ = 学生模型在对应位置的隐藏状态

> 🧠 **类比**：语言化损失确保学生"想得对"，蒸馏损失确保学生"看得准"（空间位置感知）。

---

##### 🔹 损失3：轨迹预测损失 $\mathcal{L}_{\text{ans}}$（并行预测路径点）

**教师的做法**：自回归地一个一个生成路径点坐标，如5个路径点需要60-70个文本token。

**学生的做法（创新！）**：使用 **K=5个可学习的空间token** $\{s_i\}_{i=1}^{K}$，追加在推理latent序列后面，每个空间token的输出通过MLP **并行** 映射为一个路径点：

$$\mathcal{L}_{\text{ans}} = \sum_{i=1}^{K} \|p_i - \hat{p}_i\|_2^2, \quad p_i = \text{MLP}(h'(s_i))$$

其中：
- $h'(s_i)$ = 第 $i$ 个空间token的输出隐藏状态
- $p_i$ = 预测的路径点
- $\hat{p}_i$ = 真实路径点（ground truth）
- 每个 $p_i \in \mathbb{R}^6$，编码为 $[x_{\text{single}}, y_{\text{single}}, x_{\text{left}}, y_{\text{left}}, x_{\text{right}}, y_{\text{right}}]$（前2维给单臂，后4维给双臂）

> 🧠 **类比**：教师像写字一样一笔一画写坐标（自回归），学生像盖章一样一次性把所有路径点"印"出来（并行），所以快得多！


#### 📌 阶段 4：推理增强的策略学习（连接"想"和"做"）

> 目的：把学生模型的"想法"转化为具体的机械臂动作

##### 动作模型 $\pi_\phi$

- 使用 **Diffusion Transformer（DiT）** 作为动作模型
- 具体实现：DiT-Policy（用于SimplerEnv）或 RDT（用于LIBERO和RoboTwin2.0）

##### 连接方式：

```
学生VLM ℱ_θ（冻结）
    │
    │ 空间token的早期层KV cache → 视觉规划 cₜ
    │
    ▼
┌─────────────────────────────────────┐
│  动作模型 π_φ                        │
│                                     │
│  状态编码器 → KV pairs              │
│       +                             │
│  视觉规划 cₜ → KV pairs            │
│       ↓                             │
│  Cross-Attention 同时关注两者        │
│       ↓                             │
│  扩散去噪 → 输出动作 aₜ             │
└─────────────────────────────────────┘
```

**训练目标**（模仿学习）：

$$\mathcal{L}_{\text{IL}}(\phi) = \ell(\pi_\phi(o_t, l, c_t), \hat{a}_t)$$

其中 $\ell$ 是扩散策略的去噪损失，$\hat{a}_t$ 是真实动作。

**关键设计**：
- **冻结** 学生VLM $\mathcal{F}_\theta$ 和状态编码器
- **只训练** 动作模型 $\pi_\phi$ 和线性投影层
- 用大规模机器人数据（OXE + ALOHA）训练20K次迭代

> 🧠 **类比**：学生VLM是"大脑"（负责想），动作模型是"手"（负责做）。大脑想好路径后，通过KV cache这个"神经信号"告诉手该怎么动。

### 七、为什么这样设计有效？（直觉理解）

| 设计选择 | 为什么有效 |
|----------|-----------|
| 用连续向量代替文本 | 连续空间信息密度高，6个向量≈250个文本token的信息量 |
| 偏好引导蒸馏 | 不是所有教师推理都好，只学好的，避免学到垃圾 |
| 语言化器 | 给连续空间提供"锚点"，确保latent真的编码了有意义的推理 |
| 视觉规划蒸馏 | 光有语言推理不够，机器人需要空间感知 |
| 并行空间token | 比自回归生成坐标快得多 |
| 冻结VLM只训练动作模型 | 防止"灾难性遗忘"，保留推理能力的同时学习动作 |
